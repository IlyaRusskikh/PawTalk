# Управление Linux Manager

[English](management.en.md) · [Первый сервер](first-server.ru.md)

После установки Linux Manager откройте терминальное меню командой `sudo pawtalkctl tui`.
В уже открытом SSH-сеансе используйте ту же команду. Для запуска напрямую по SSH
выделите терминал командой `ssh -t user@host sudo pawtalkctl tui`.

Выберите пункт стрелками вверх и вниз и нажмите Enter или щёлкните по пункту
в терминале с поддержкой мыши. Page Up и Page Down прокручивают журнал, Esc
возвращает в меню. В простых терминалах показывается меню с номерами.

Действия сгруппированы в разделах «Обзор», «Сеть», «Безопасность и история»,
«Обновления», «Резервные копии» и «Диагностика». Пункт «Назад» и клавиша Esc
возвращают к списку разделов.

В меню видны состояние и адрес сервера, версии компонентов, журнал и диагностика.
Можно запустить или остановить сервер, получить ссылку первого администратора до
завершения настройки, изменить адрес и базовый порт, настроить лимит истории и
переключить интерфейс между русским и английским. Сквозное шифрование обязательно.

Проверка, установка и автообновление настраиваются отдельно для Server и Manager.
Чтобы выбрать релиз Server с диска, укажите его подписанный JSON-манифест. Linux
скачает образ с указанным в нём digest. Мастер первого запуска принимает
опубликованный релиз или подписанный манифест.

В меню можно создать, восстановить или удалить резервную копию.
Для восстановления выберите копию по дате в UTC и имени, затем подтвердите действие.
Восстановление возвращает активный сервер к состоянию копии и прерывает текущие звонки.
Создание копии тоже временно останавливает работающий сервер.

Для скриптов и прямого управления используйте команды `pawtalkctl` с sudo.
Сгенерированными файлами Compose, томами Docker и состоянием установки управляет Manager.

~~~bash
sudo pawtalkctl status
sudo pawtalkctl doctor
sudo pawtalkctl logs
sudo pawtalkctl start
sudo pawtalkctl stop
sudo pawtalkctl update check
sudo pawtalkctl manager check
~~~

`status` показывает состояние, `doctor` диагностирует установку, `logs` выводит журналы. `update check` и `manager check` независимо обнаруживают опубликованные релизы **без установки**. Healthcheck контейнера не доказывает работу голоса/UDP извне.

Поддерживаемые runtime-параметры меняются через контроллер с резервным копированием, остановкой и проверкой:

~~~bash
sudo pawtalkctl configure PAWTALK_CHAT_MAX_MB=256 PAWTALK_BACKUP_KEEP=5 --yes
~~~

Уменьшение лимита истории может удалить старые сообщения. `--yes` явно подтверждает изменение. Не запускайте `configure` одновременно с обновлением или backup. Изменение адреса или порта прерывает звонки, а старые ссылки могут перестать работать. Для смены IPv4 нужен Server с поддержкой `serve rebind`. При смене IP выпускается новый TLS-сертификат. Обновите правила брандмауэра и маршрутизатора для новых портов.

Для диагностики служб:

~~~bash
sudo systemctl status docker --no-pager
sudo systemctl list-timers --all 'pawtalk-*'
sudo journalctl -u pawtalk-health.service -u pawtalk-update.service -n 100 --no-pager
~~~

Таймер здоровья ограниченно восстанавливает нездоровый работающий контейнер, но не запускает контейнер, остановленный администратором намеренно.
