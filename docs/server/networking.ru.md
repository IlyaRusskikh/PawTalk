# Сеть и приглашения

[English](networking.en.md) · [Документация](../README.ru.md)

Обычно постоянный сервер использует такие порты (базовый 18443):

| Порт | Назначение | Доступ |
| --- | --- | --- |
| TCP 18443 | TLS, API и сигнализация | Участники |
| TCP 18444 | Передача голоса по TCP | Участники |
| UDP 18445 | Передача голоса по UDP | Участники |
| TCP 18446 | Внутреннее управление медиасервером | Только loopback — не открывать наружу |

Последние три — смещения +1, +2 и +3 от базового порта. В Linux Manager использует Compose с host networking; публикация портов Docker не заменяет правила брандмауэра и провайдера.

Для доступа из интернета нужен доступный публичный IPv4 и правильные сетевые правила. Мешать могут CGNAT, VPN/прокси, NAT loopback и проброс портов. Успех проверки TLS/API **не означает**, что работают UDP и реальный звонок. Проверяйте из другой сети.

**Адрес приглашения:** клиент использует адрес сервера, сохранённый у него. Если вы подключились по LAN IP, новые приглашения также могут содержать локальный адрес. Предпочтительно изменить адрес через меню сервера в клиенте, сохранив TLS-отпечаток. Если из LAN внешнее IP недоступно, в скопированной ссылке для внешнего участника замените **только адрес/при необходимости внешний порт**, сохранив отпечаток и весь фрагмент (`#...`). Не публикуйте приглашение.
