# Совместимость опубликованных компонентов

[English](compatibility.en.md) · [Документация](../README.ru.md)

Проверенная 15 ноября 2026 года совместимая комбинация опубликованных **preview API 2**:

| Компонент | Релиз |
| --- | --- |
| Windows Client | [client-v0.12.1](https://github.com/IlyaRusskikh/PawTalk/releases/tag/client-v0.12.1) |
| Постоянный Server | [server-v0.11.1](https://github.com/IlyaRusskikh/PawTalk/releases/tag/server-v0.11.1) |
| Windows/Linux Manager | [manager-v0.5.1](https://github.com/IlyaRusskikh/PawTalk/releases/tag/manager-v0.5.1) |

Это **датированная проверенная комбинация, а не закрепление версий для установки**. Для более новых выпусков сверяйте требования в [каталоге загрузок](https://ilyarusskikh.github.io/PawTalk/downloads/) и [описаниях релизов](../../releases/README.ru.md).

API 2 требует серверный API/data schema 2 и обязательное E2EE. **Клиенты и серверы API 1 несовместимы с API 2; автоматической миграции старого членства, истории, паролей и резервных копий нет.** Старые данные сохраняйте отдельно, не импортируя их как API 2. Обновление Manager не заменяет установленный Server автоматически.

У Server и Manager собственные теги выпусков, хотя пакет Manager содержит инструменты Windows и Linux. Отдельного номера версии Manager для каждой ОС нет.

## Подготовленные исходники выпусков

Исходники выпусков [Client 0.13.0](../../releases/client-v0.13.0.ru.md) и
[Server 0.12.0](../../releases/server-v0.12.0.ru.md) сохраняют API/data schema 2.
Сначала обновляйте Server для доступа к перечисленным ниже capabilities. Manager
0.5.1 совместим и устанавливает Server отдельно; новый Server не встроен в Manager.
Эта комбинация исходников не меняет каталог опубликованных выпусков.

## Capabilities новых функций в исходном коде

API/data schema остаются равными 2; добавлены необязательные activity-v1, attachment-removal-v1, link-cancel-v1, server-avatar-v1, polls-v1, system-poll-results-v1, chat-events-v1, server-events-v1 и message-events-v1. Сначала обновляйте Server. Без capabilities основной чат/голос доступны; создание аватара/опроса скрыто, неподдерживаемое удаление вложения/отмена привязки сообщает о необходимости обновления Server. Старый Client игнорирует дополнительные поля и показывает опрос текстом вопроса без голосования. Муты уведомлений и стрелка перехода — локальные функции Client. При наличии chat-events-v1 активный чат использует аутентифицированный WebSocket; со старыми Server сохраняется опрос. API и контракты выпуска Manager не меняются.

В базы API 2 добавляются отдельные таблицы без переписывания идентичностей и прежних таблиц; это не миграция API 1. См. [контракты реализации](../../architecture/chat-features.ru.md).

media-files-v1 разрешает зашифрованные вложения до 50 МБ; старые Server API 2 сохраняют лимит 2 МБ. checklists-v1 включает создание, редактирование и отметки списков. Старые Client показывают названия списков, игнорируя дополнительные зашифрованные поля; просмотр новых вложений там отсутствует. Для всех функций обновите Server перед Client. Контракты Manager не изменены.

Необязательная capability checklist-events-v1 передаёт версии отметок через существующий WebSocket сообщений. На старых Server Client сохраняет резервный опрос.

`media-gallery-v1`: до десяти зашифрованных файлов с готовыми кадрами видео, не более двадцати уникальных ID вложений на сообщение. Новый Client проверяет capability перед отправкой галереи; старые сообщения с одним файлом поддерживаются. Старый Client нужно обновить для просмотра галерей. Версии API/data и миграции Manager не меняются.
