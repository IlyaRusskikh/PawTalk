# Как помочь пользователям найти PawTalk

После выпуска 0.1.0 главная задача — понятно объяснить назначение проекта,
дать работающую ссылку на установщик и помочь создать первую комнату.
Этот список предназначен для сопровождающих. Он не означает, что настройки
GitHub уже изменены или материалы опубликованы на сторонних площадках.

## 1. About и topics на GitHub

В репозитории откройте шестерёнку рядом с **About**. Рекомендуемое описание:

> Open-source, self-hosted voice chat for Windows. Account-free rooms, push-to-talk, RNNoise noise suppression and a Linux Docker server.

Оно заменяет «vibecoded p2p or p2s2p simple voicechat»: пользователю важнее
платформа и назначение. Текущая архитектура использует медиасервер LiveKit,
поэтому `p2p` не стоит использовать как обещание прямой передачи между клиентами.

Подходящие topics:

```text
voice-chat, self-hosted, windows, webrtc, livekit, electron, push-to-talk,
noise-suppression, rnnoise, docker, gaming, typescript, golang
```

Topics помогают искать проекты по назначению внутри GitHub:
[документация GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics).
Поле Website заполняйте адресом отдельного сайта, когда он будет опубликован.
Пока пользователям можно передавать [страницу релизов](https://github.com/IlyaRusskikh/pawtalk/releases).
Релиз 0.1.0 помечен как pre-release: ссылки на `/releases/latest` для него не подходят.

## 2. Скриншоты и короткая демонстрация

Три актуальных скриншота уже добавлены в `website/assets/` и оба README.
Как переснять их в изолированном профиле: [website/README.md](../website/README.md).

При обновлениях сохраняйте актуальные изображения главного экрана и
настроек звука. Для скриншота разговора используйте тестовые никнеймы; скройте адрес, приглашение,
пароль, ключ E2EE и личные данные. Сохраняйте изображения в `website/assets/`,
используйте относительные ссылки и понятные alt-тексты на языке README.

Короткое видео или GIF может показать путь «создать → пригласить → говорить».
Записывайте его на тестовой комнате; не публикуйте действующие приглашения.
После изменений интерфейса обновляйте изображения вместе с инструкциями.

## 3. Отдельная страница для поиска

Статические страницы на русском и английском уже подготовлены в `website/`.
Они ещё не опубликованы. Инструкция ручного запуска GitHub Pages и проверки
URL: [website/README.md](../website/README.md).

Для публикации используйте подготовленный GitHub Pages workflow.
Не публикуйте корень приложения как сайт:
`index.html` относится к Electron-клиенту, а браузерный предпросмотр
не является готовым веб-клиентом PawTalk.

Для сайта достаточно отдельных английской и русской страниц со следующим:

- Заголовок с названием и назначением: «PawTalk — self-hosted voice chat for Windows».
- Описание аудитории, возможностей и текущих ограничений.
- Кнопка скачивания, версия и ссылка на описание выпуска с контрольными суммами.
- Настоящие скриншоты и короткая инструкция первой комнаты.
- Ответы на вопросы о платформах, портах, CGNAT, сервере и E2EE.
- Ссылки на исходники, лицензию, документацию и обратную связь.

После выбора окончательного URL настройте осмысленные `title` и description,
canonical URL и языковые ссылки между страницами. Для превью ссылок добавьте
Open Graph с настоящим скриншотом. После публикации можно подтвердить сайт в
Google Search Console и проверить индексирование. Файлы `robots.txt` или sitemap
в исходниках Electron-приложения сами по себе не меняют индексирование GitHub.

Google рекомендует полезный понятный текст, содержательные заголовки и доступные
ссылки; `meta keywords` не используется, а повторение ключевых слов не помогает:
[SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).
Ни README, ни сайт не гарантируют позиции или сроки появления в поиске.

## 4. Где рассказать о проекте

После проверки первого пользовательского сценария подготовьте небольшой анонс:
для кого приложение, что уже работает, скриншот, как скачать и какие ограничения
есть у preview. Для русскоязычной аудитории можно подготовить статью с опытом
разработки и развёртывания; для международной — краткую демонстрацию self-hosted
voice chat с честным указанием русского интерфейса и Windows-клиента.

Выбирайте сообщества про self-hosting, открытое ПО и небольшие игровые группы.
Перед публикацией проверьте правила сообщества о саморекламе. Подборки проектов
пополняйте только там, где PawTalk подходит по критериям; не создавайте
однотипные ссылки ради поисковой выдачи.

## 5. Что проверять после изменений

- Пользователь видит, что это Windows-клиент, а Linux — серверная платформа.
- Ссылка скачивает установщик; Source code не выдаётся за готовое приложение.
- Статус preview, язык интерфейса и отсутствие автообновлений указаны явно.
- Инструкции в двух README совпадают, название asset и номер версии актуальны.
- Вопросы и баги можно отправить через GitHub Issues без передачи секретов.
- После нового релиза обновлены ссылки в README и соответствующие инструкции.

Смотрите, какие вопросы повторяются в issues, на каком шаге люди застревают
и какие внешние ссылки приводят заинтересованных пользователей. Эти наблюдения
помогут выбрать следующую доработку документации и приложения.
