# Проверка селфхоста до установки Voicecord

Нужны Windows 10/11 и встроенный Windows PowerShell 5.1. Voicecord, Node.js,
установщик и дополнительные утилиты не нужны. Запускайте в обычной консоли
PowerShell: права администратора не требуются.

## Запуск

Если Voicecord уже установлен, откройте **«Создать комнату»** и нажмите
**«Проверить»** рядом с «Могу ли я хостить в интернет?». Приложение запускает
эту же проверку для выбранного базового порта в скрытом процессе Windows
PowerShell. Результат появляется после завершения и очистки пробросов.
Зелёный статус означает подтверждённый TCP и UDP; жёлтый — неподтверждённый
интернет-доступ либо ошибку сервиса (с разными пояснениями). Закрытие модалки
отменяет проверку, создание комнаты ждёт освобождения портов. Изменение порта
сбрасывает результат. Пароль комнаты и секрет E2EE проверке не передаются.
При ошибках показываются пояснение и отдельные результаты для двух TCP-портов
и UDP. Временные ошибки запросов check-host.net повторяются до двух раз
в пределах общего тайм-аута; ошибка сервиса не означает невозможность хостинга.
Скрипт проверяет сеть из PowerShell: разрешение брандмауэра для него не заменяет
разрешение для самого Voicecord после создания комнаты.

Скопируйте команду в **Windows PowerShell**:

```powershell
$code = (Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/IlyaRusskikh/voicecord/main/scripts/check-selfhost.ps1').Content; & ([ScriptBlock]::Create($code))
```

Команда загружает текст скрипта из репозитория и выполняет в памяти, не сохраняя
файл. Она работает после публикации скрипта в ветке `main`. Чтобы вообще не
загружать код командой, откройте [скрипт](../scripts/check-selfhost.ps1), скопируйте
его содержимое целиком и вставьте в PowerShell. Для запуска из исходников:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-selfhost.ps1
```

При запуске из уже открытого cmd/PowerShell скрипт вернёт управление в ту же
консоль, результаты останутся на экране. Для запуска двойным щелчком используйте
[check-selfhost.cmd](../scripts/check-selfhost.cmd) рядом с `.ps1`: после проверки
он ждёт нажатия клавиши, поэтому окно не закрывается сразу.

Для другого базового порта:

```powershell
$code = (Invoke-WebRequest -UseBasicParsing 'https://raw.githubusercontent.com/IlyaRusskikh/voicecord/main/scripts/check-selfhost.ps1').Content; & ([ScriptBlock]::Create($code)) -Port 19443
```

Если позднее создаёте комнату с другим базовым портом, проверьте его заново.

## Что делать во время проверки

1. Для однозначной проверки при необходимости отключите VPN/прокси.
   Скрипт предпочитает физический IPv4-интерфейс с основным шлюзом;
   при нескольких подключениях проверьте выведенный LAN-адрес.
   Если обнаружено несколько шлюзов IPv4, скрипт предупредит об этом. UDP-сокет
   привязан к выбранному LAN-адресу, чтобы ответы использовали адрес проброса.
2. Скрипт проверит занятость TCP 18443, TCP 18444 и UDP 18445.
   Внутренний TCP 18446 не занимает: для внешней проверки он не нужен.
   Затем попробует создать через UPnP пробросы **двух TCP-портов и UDP 18445**.
   Если Windows покажет запрос брандмауэра, разрешите доступ для теста.
3. Скрипт автоматически проверяет **оба TCP-порта** через
   [API check-host.net](https://check-host.net/about/api). Открывать сайт и вводить
   порты не нужно: для каждого порта запускаются два внешних проверяющих узла,
   выводится ссылка на отчёт, затем скрипт получает результат через API.
   Тайм-ауты и ошибки сервиса не считаются успехом и не доказывают невозможность селфхоста.
4. Для UDP скрипт также автоматически обращается к check-host.net,
   заранее получает адреса проверяющих узлов и запускает тест с двух узлов. Он отвечает
   коротким UDP-эхом только известным узлам сервиса. Проверка успешна, когда
   скрипт получил пакет, отправил ответ и сервис подтвердил получение ответа.
   Сервис получает публичный IP и порт, создаёт публичный отчёт; ссылка выводится
   в консоли. Пароли и ключи не передаются. Отключить внешний UDP-тест можно
   параметром `-SkipUdpCheck`, TCP-тест — `-SkipTcpCheck`. Если WAN-адрес роутера не публичный или отличается
   от адреса на 2ip, задайте `-PublicIP <IPv4 с 2ip>`.
5. При недоступном UPnP можно вручную пробросить TCP-порты и UDP 18445 на выведенный
   LAN-адрес и выполнить проверку, пока скрипт слушает порты.
   Автоматический UDP-тест запускается один раз в начале: после ручной настройки
   перезапустите скрипт для новой внешней проверки.
6. Ручная проверка через [2ip](https://2ip.io/ru/check-port/) остаётся запасным
   вариантом при недоступности API: проверьте оба TCP-порта и нажмите **T**,
   только если оба открыты, чтобы записать этот результат в итог.
   Скрипт также автоматически учитывает входящие TCP-соединения от
   публичных адресов на обоих портах. Когда подтверждены оба TCP-порта и полный
   обмен UDP, скрипт сразу выводит блок **RESULT**, освобождает порты и удаляет
   свои пробросы. Ждать тайм-аут не нужно. Для досрочного завершения нажмите
   **Q**; без полного успеха скрипт завершится не позднее 180 секунд ожидания.

Существующие UPnP-пробросы скрипт не заменяет. Если порт уже проброшен,
используйте другой базовый порт, чтобы проверить именно автоматический проброс.
NAT-PMP этим скриптом не проверяется; приложение также поддерживает этот способ,
поэтому неудача UPnP сама по себе не исключает автоматический проброс в Voicecord.

## Как читать результат

- **PASS: TCP … confirmed by an external checker:** сервис подтвердил
  соединение с конкретным TCP-портом. Для TCP-успеха нужны оба порта.
- **Оба порта открыты на 2ip (запасной способ):** входящий TCP из интернета
  подтверждён для проверенных портов и текущей конфигурации сети/брандмауэра.
- **SUCCESS:** подтверждены оба TCP-порта и полный обмен UDP с внешним узлом.
- **PARTIAL SUCCESS:** подтверждена только часть проверок; итог указывает какая.
- **UDP round trip NOT CONFIRMED:** ответ снаружи не подтверждён. Тайм-аут,
  недоступность сервиса или результат «Open or filtered» не считаются успехом.
  Получение UDP-пакета без подтверждения ответа означает только входящую доступность.
- **Проброс создан, но порты закрыты:** проверьте брандмауэр, выбранный сетевой
  интерфейс, VPN, дополнительный роутер и NAT у провайдера.
- **UPnP недоступен:** может помочь включение UPnP или ручной проброс.
- **Порт занят локально:** закройте использующую его программу или выберите другой порт.

При отказе роутера скрипт показывает операцию и UPnP-код с описанием, например
`UPNP_725: AddPortMapping` — роутер требует бессрочную аренду, которую тест не
создаёт. Если код отсутствует, выводится операция и HTTP-статус. Сам по себе
HTTP 500 не объясняет причину: код 714 при запросе существующей записи означает
её отсутствие и обрабатывается скриптом как разрешение перейти к созданию проброса.

Запись `TCP connection accepted` означает факт подключения. Для автоматического
TCP-успеха нужны подключения на обоих портах от публичных адресов, отличных от
вашего WAN/заданного PublicIP. Подключения через localhost/LAN не дают успеха.
Личность TCP-клиента скрипт не устанавливает: это не обязательно 2ip.
Внешняя проверка каждого порта ограничена 45 секундами. UDP-эхо ограничено
пакетами до 256 байт и 16 ответами без
увеличения размера. До отправки проверки загружается список адресов узлов,
чтобы ответить на пакет, даже если HTTP-подтверждение запуска ещё не пришло.
Скрипт не отправляет UDP первым: пакет должен прийти извне через проброс.
Качество связи и реальная работа голоса **не подтверждаются**. После установки у Voicecord будут свои разрешения
брандмауэра; разрешение, выданное PowerShell, не распространяется на приложение.

При завершении скрипт закрывает слушатели и удаляет только свои UPnP-пробросы,
сверяя их адрес и уникальную метку. Срок каждого проброса — 300 секунд: даже при
принудительном закрытии консоли он должен истечь на роутере. Роутеры, требующие
постоянных пробросов, не поддерживаются этим тестом. Ручные пробросы и разрешения
брандмауэра скрипт не меняет и не удаляет; после теста уберите их самостоятельно.
Отчёты на диск не записываются.

Синтетическая проверка SOAP, конечного срока проброса, очистки, UDP-эха,
проверки узлов сервиса, TCP API, отсутствия ложного успеха при ошибках/тайм-ауте
и досрочного завершения входит в
`npm test` на Windows. Она не заменяет проверку реального роутера и внешней сети.
