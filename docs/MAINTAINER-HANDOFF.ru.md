# Передача документации на аудит

[English](MAINTAINER-HANDOFF.en.md) · [Документация](README.ru.md)

Ветка заменяет пользовательскую и техническую документацию **с нуля**, переносит исходные тела релизов в корневой `releases/` и меняет пути в скриптах, правилах агентов, сайте и CI. **PR не создан**, merge/теги/релизы не выполнялись. Следующие проверки нужно выполнить в локальном checkout или Codex.

## Обязательные локальные проверки

~~~bash
git fetch origin
git switch docs/complete-refresh-2026-11-16
git status --short
node tooling/ci/check-docs.mjs
node tooling/ci/check-release-notes.mjs
node --test tests/infrastructure/documentation.test.mjs tests/release/release-notes.test.mjs tests/infrastructure/agent-infrastructure.test.mjs
node tooling/ci/check-agents.mjs
node tooling/ci/check-website.mjs
npm run check:public
~~~

Для полных тестов ставьте зависимости через `npm ci` только в изолированном окружении. Запустите подходящие [CI](../.github/workflows/check.yml), включая тесты release-candidate. Ошибки разбирайте, а не пропускайте. Проверьте скрипты/фикстуры на остаточные пути `docs/releases/`. **Не** публикуйте релизы и не создавайте теги.

## Ручной аудит

1. Сравните смысл каждой пары RU/EN. Проверьте названия элементов интерфейса в **опубликованных** Client и Windows Manager.
2. Проверьте команды Linux Manager на безопасном поддерживаемом Debian 12 или Ubuntu 24.04 LTS. Не выполняйте install/uninstall/restore на production без копии.
3. Сверьте техническую архитектуру с исходниками опубликованных тегов и фактическими Go API/SQLite. Эти страницы — **карта**, а не исчерпывающая машинная спецификация endpoint.
4. Проверьте ссылки и статический Pages на обоих языках. Старые скриншоты сайта 0.7.x остаются **историческими иллюстрациями**; для актуальных изображений нужен опубликованный Client API 2 и обезличенный профиль.
5. Проверьте локализованные `releases/<tag>.en.md` и `.ru.md` по каноническим локальным исходникам `releases/<tag>.md`. Их байты сохранены из прежнего дерева документации для digest/CI; они не обязательно совпадают с публичными описаниями Release. См. [зафиксированные расхождения](../releases/README.ru.md). Три неудачных кандидата не являются релизами.
6. Проверьте хронологию ранних общих тегов Voicecord/PawTalk. Эти теги сами по себе не подтверждают отдельные бинарники Client/Server/Manager.

## Что осталось непроверенным

Среда редактирования через GitHub не позволяет запустить npm/Go/Python/Windows/Linux интеграционные тесты или пересобрать подписанные файлы и новые скриншоты. **Об успешном прогоне тестов не заявляется.** Исторические снимки релизов могут содержать ссылки на файлы **старых** тегов; это намеренная неизменяемая история, а не инструкция текущего API.

Не открывайте PR без поручения владельца. Исправления можно вносить в эту же ветку, затем передать diff и результаты аудита владельцу.
