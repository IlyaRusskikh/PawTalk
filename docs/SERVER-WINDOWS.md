# Постоянный сервер PawTalk на Windows — Docker Swarm в Linux VM

Если домашний Windows-ПК работает постоянно, на нём можно держать отдельный
сервер PawTalk. Комната не зависит от запущенного Windows-клиента: вы можете
закрыть приложение, а друзья продолжат общаться. ПК, виртуальная машина и
Docker должны оставаться включёнными; во время сна или перезагрузки связи нет.

Серверный образ PawTalk — **Linux amd64/arm64**, а Swarm-стек использует
`host networking`. Здесь Docker Engine и одноузловой Swarm работают **в Linux VM
на Windows**, а не в режиме Windows containers. Для этого сценария не нужен
Docker Desktop. У Docker Desktop есть собственная реализация host networking,
но она не равнозначна отдельному Linux-хосту; её применимость к этому стеку
не подтверждена. См. [сеть Docker host](https://docs.docker.com/engine/network/drivers/host/).

Ниже — вариант с Hyper-V на Windows 10/11 Pro или Enterprise x64.
Hyper-V недоступен в Home: понадобится другая виртуальная машина с сетевым
мостом (например, [VirtualBox, Bridged Networking](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/networkingdetails.html))
либо отдельный Linux-ПК/VPS. Шаги Hyper-V и его автозапуска к VirtualBox не относятся.
Этот домашний сценарий ещё **не прошёл реальную приёмку проекта**; инструкция
не означает, что внешняя сеть и голос уже проверены на вашем оборудовании.

## 1. Подготовьте ПК и доступ из интернета

- Включите аппаратную виртуализацию в UEFI/BIOS, если она выключена.
- Для Linux VM можно начать с 2 виртуальных CPU, 2 ГиБ RAM и диска 20 ГиБ.
  Это начальная конфигурация, а не измеренная гарантия вместимости комнаты.
  Оставьте ресурсы Windows и играм; историю, образы, кэш обновлений и резервные
  копии нужно учитывать отдельно.
- Для друзей из интернета нужны публичный IP и возможность пробросить порты
  на роутере. CGNAT провайдера не обходится установкой Docker или Swarm:
  запросите публичный адрес у провайдера либо используйте VPS.
- Для этой инструкции желательно иметь **постоянный публичный IP**. PawTalk
  сохраняет IP в состоянии комнаты: динамический DNS сам по себе не позволяет
  менять его. При смене IP потребуется процедура из
  [раздела о сохранении комнаты](SERVER.md#где-данные-и-как-сохранить-комнату).
  Для комнаты только в LAN достаточно постоянного локального IP виртуальной машины.

## 2. Создайте Linux VM с адресом в домашней сети

Следующие действия выполняются **в Windows**.

1. Откройте «Включение или отключение компонентов Windows», включите **Hyper-V**
   и перезагрузите ПК. Нужны права администратора.
   [Установка Hyper-V](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/Install-Hyper-V).
2. Откройте **Диспетчер Hyper-V → Диспетчер виртуальных коммутаторов**.
   Создайте **внешний** коммутатор, выберите физический сетевой адаптер,
   подключённый к роутеру (предпочтительно Ethernet), и оставьте разрешение
   управляющей ОС использовать этот адаптер. Применение может кратко прервать сеть.
   Не используйте `Default Switch`: в этой инструкции VM должна получать
   собственный адрес от домашнего роутера, без дополнительного NAT Windows.
   [Внешний коммутатор](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/create-a-virtual-switch-for-hyper-v-virtual-machines).
3. Создайте VM с именем **PawTalkServer**, поколением 2 и ресурсами из шага 1.
   Подключите её к созданному внешнему коммутатору. Скачайте установочный ISO
   [Debian amd64](https://www.debian.org/distrib/) или
   [Ubuntu Server amd64](https://ubuntu.com/download/server) с официального сайта
   и подключите его как DVD. При включённом Secure Boot выберите шаблон
   **Microsoft UEFI Certificate Authority** для Linux
   ([настройки Secure Boot](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/learn-more/Generation-2-virtual-machine-security-settings-for-Hyper-V)).
   [Создание VM](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/get-started/create-a-virtual-machine-in-hyper-v).
4. Установите Linux, создайте администратора и включите **OpenSSH server**.
   Графическая среда не нужна. После установки загрузитесь с виртуального диска.
5. В консоли **Linux VM** определите адрес и MAC сетевого интерфейса:

   ```sh
   ip -br -4 addr
   ip -br link
   ```

   В DHCP-настройках роутера закрепите за MAC постоянный локальный IPv4.
   Далее `192.168.1.50` — только пример адреса VM; подставляйте свой.
   Проверьте, что VM имеет доступ в интернет.

Из **Windows PowerShell** подключитесь к VM, заменив имя пользователя и адрес:

```powershell
ssh youruser@192.168.1.50
```

Если SSH недоступен, проверьте службу SSH, firewall Linux и подключение VM к
внешнему коммутатору. До установки сервера VM должна быть доступна из вашей LAN.

## 3. Установите Docker Engine и разверните PawTalk

Далее команды выполняются **в Linux VM**, через её консоль или SSH.
Перейдите к [SERVER.md](SERVER.md) и выполните шаги **1–7**: VM здесь играет
роль Linux-сервера вместо VPS. Важные отличия:

| Настройка | Что указать дома |
| --- | --- |
| Права | В Ubuntu выполните `sudo -i`; в Debian войдите под `root` или используйте настроенный `sudo`. |
| Docker | Установите **Docker Engine для Linux** внутри VM по шагу 2. Включите `systemctl enable --now docker`. |
| `docker swarm init --advertise-addr` | Локальный IP **VM**, например `192.168.1.50`, а не IP Windows и не внешний IP роутера. Если Swarm уже активен, повторно его не создавайте. |
| `PAWTALK_PUBLIC_IP` в `.env` | Для интернета — публичный IP роутера; для комнаты только в LAN — постоянный локальный IP VM. Выберите режим до первого запуска. |
| Файлы и данные | `/opt/pawtalk` и Docker volume находятся **внутри VM**, на её виртуальном диске. Настройки и volume сохраняются при перезагрузке. |
| E2EE | По желанию настройте до первого запуска по [инструкции](E2EE.md); секретный ключ создавайте на доверенном клиентском ПК. В VM переносится только его отпечаток. |

Например, при ещё не включённом Swarm в VM команда будет такой:

```sh
docker swarm init --advertise-addr 192.168.1.50
```

Не пропускайте назначение метки `pawtalk.data=true`, загрузку файлов одной
версии, создание внешнего volume и проверки запуска из `SERVER.md`.
Оставьте одну реплику: это одна комната с локальной SQLite, а не кластер
с репликацией данных.

### Проброс портов на домашнем роутере

В шаге 5 `SERVER.md` вместо firewall хостинга настройте роутер:

| Внешний порт | Протокол | Куда направить |
| --- | --- | --- |
| `18443` | TCP | `192.168.1.50:18443` — HTTPS и сигнализация |
| `18444` | TCP | `192.168.1.50:18444` — резервный голосовой транспорт |
| `18445` | UDP | `192.168.1.50:18445` — основной голосовой транспорт |

Подставьте адрес **VM**, не Windows-хоста. Внешний и внутренний номера портов
должны совпадать. При другом `PAWTALK_PORT` используйте базовый TCP-порт,
TCP `PORT+1` и UDP `PORT+2`. Разрешите их в firewall Linux, если он включён.
При внешнем коммутаторе не требуется `netsh portproxy` или второй проброс
с Windows в VM. Не отключайте firewall Windows целиком; при фильтрации
виртуального адаптера защитным ПО настройте разрешения для нужного трафика.

TCP `18446`, SSH и управляющие порты Swarm в интернет не пробрасывайте.
Для комнаты только в LAN проброс на роутере вообще не нужен.
При двойном NAT настройте оба роутера либо устраните лишний NAT; при CGNAT
обычного проброса недостаточно.

## 4. Включите автозапуск и отключите сон

В **Windows PowerShell от администратора** настройте VM с именем из шага 2:

```powershell
Set-VM -Name 'PawTalkServer' -AutomaticStartAction Start -AutomaticStartDelay 30 -AutomaticStopAction ShutDown
Get-VM -Name 'PawTalkServer' | Select-Object Name, State, AutomaticStartAction, AutomaticStopAction
```

Это запускает VM после старта Hyper-V и запрашивает корректное завершение Linux
при выключении Windows. [Параметры Set-VM](https://learn.microsoft.com/en-us/powershell/module/hyper-v/set-vm).
В настройках электропитания Windows отключите автоматический сон и гибернацию
при питании от сети. На ноутбуке также проверьте действие при закрытии крышки.
Экран можно выключать; VM и ПК должны продолжать работать.

Автозапуск состоит из трёх частей: Windows запускает VM, Linux запускает Docker,
Swarm восстанавливает сервис `pawtalk_server`. Открывать PawTalk-клиент,
держать SSH или консоль Hyper-V открытыми для работы комнаты не нужно.

## 5. Проверьте комнату и восстановление после перезагрузки

1. В VM проверьте `docker stack services pawtalk`: ожидается `1/1`.
   Выполните healthcheck и `serve info` по шагам 6–7 `SERVER.md`.
   Сохраните пароль из первого запуска; он не входит в ссылку `serve info`.
2. Подключите Windows-клиент по полному приглашению с отпечатком сертификата.
   Для интернет-комнаты проверьте двух клиентов **из разных сетей**, например
   второй ПК через мобильную раздачу. Проверьте речь в обе стороны и чат.
   Один ответ `/healthz` не подтверждает передачу голоса.
3. Если внешняя связь работает, а из домашней сети по публичному IP подключиться
   не удаётся, проверьте поддержку **NAT loopback / hairpin NAT** роутером.
   Не подменяйте IP в приглашении наугад: он также используется для голосового
   соединения. Для постоянной интернет-комнаты нужен доступ к её публичному
   адресу и из домашней сети.
4. В удобное время перезагрузите Windows. До входа в клиент убедитесь с другого
   ПК, что VM и комната поднялись. Проверьте прежнее приглашение, пароль,
   сохранённую переписку и голос. Перезагрузка прерывает текущие звонки.

Проблемы с портами: [пошаговая сетевая диагностика](SERVER.md#проверка-доступа-из-интернета-и-проброса-портов).
Обновления и откат: [SWARM.md](SWARM.md), все команды выполняются в Linux VM.
Резервное копирование: [сохранение комнаты](SERVER.md#где-данные-и-как-сохранить-комнату).
Храните копию volume отдельно от виртуального диска: удаление VM вместе с диском
уничтожит единственную локальную копию комнаты. Снимок работающей VM не заменяет
согласованную резервную копию данных по инструкции.
