# Первый разговор в Voicecord

Эта инструкция — для готового Windows-приложения, без сборки исходников.
Нужны два Windows-ПК и гарнитуры. Сначала проверьте разговор в одной локальной
сети; доступность комнаты через интернет проверяется отдельно.

## 1. Установите клиент

На обоих ПК скачайте `Voicecord.Setup.0.3.0.exe` из
[выпуска 0.3.0](https://github.com/IlyaRusskikh/voicecord/releases/tag/v0.3.0).
Архив Source code содержит исходники, а не готовое приложение. Для установки
не нужны Node.js, Go, Docker или права администратора на роутере.

Установщик пока не подписан: Windows может показать предупреждение о неизвестном
издателе. Сверьте источник скачивания и SHA-256 с `SHA256SUMS.txt` из того же
релиза. В PowerShell в папке скачивания:

```powershell
Get-FileHash -LiteralPath '.\Voicecord.Setup.0.3.0.exe' -Algorithm SHA256
```

Сравните полученный `Hash` со строкой установщика в `SHA256SUMS.txt` (регистр
букв не важен). Если хеш отличается, не запускайте файл, скачайте его заново
с проверенной страницы. Контрольная сумма проверяет совпадение с опубликованным
файлом, а не заменяет цифровую подпись или аудит безопасности.

## 2. Проверьте звук на обоих ПК

1. Откройте **Настройки → Обо мне**, задайте разные узнаваемые никнеймы.
2. Выберите микрофон и динамик в разделе **Голос**.
3. Нажмите **Проверка микрофона**, произнесите фразу и убедитесь, что слышите себя.
4. Остановите прослушивание. Для первого разговора используйте наушники,
   активацию голосом и настройки обработки по умолчанию.

Если захват не запускается, проверьте разрешения Windows на микрофон для
классических приложений и выбранное устройство. Если звук слышен только при
нажатии клавиши, проверьте, не выбран ли режим Push-to-Talk.

## 3. Создайте локальную комнату

На первом ПК нажмите **Создать комнату**, задайте название и пароль от 8 символов,
оставьте стандартный порт **18443**, затем нажмите **Создать и войти**.
Для первой проверки можно оставить экспериментальное E2EE выключенным.

В окне приглашения выберите локальный уровень сети и LAN-адрес, доступный второму
ПК. Передайте полное приглашение лично. Не используйте `127.0.0.1` для другого ПК:
этот адрес всегда указывает на компьютер самого подключающегося.

На втором ПК откройте **Присоединиться к комнате** и вставьте приглашение целиком.
Оно уже содержит пароль. Проверьте, что оба участника отображаются и слышат
друг друга. Убедитесь, что mute и deafen выключены, а индивидуальная громкость
собеседника больше нуля.

Если LAN-вход не проходит, проверьте общий сегмент сети, изоляцию клиентов в
гостевом Wi-Fi и разрешения Windows Firewall на ПК хоста. Не отключайте firewall
целиком. Входящие порты по умолчанию: **TCP 18443**, **TCP 18444**, **UDP 18445**.
При другом порте комнаты используются TCP-порт комнаты, TCP +1 и UDP +2.

## 4. Проверьте доступ через интернет отдельно

Попросите друга из другой сети попробовать глобальное приглашение. Подключение
из своей LAN по собственному публичному IP не доказывает внешнюю доступность:
маршрутизатор может не поддерживать NAT loopback.

Автопроброс UPnP/NAT-PMP не гарантирует доступность. Проверьте проброс трёх
портов и firewall. При CGNAT, двойном NAT или ограничениях провайдера используйте
VPS с публичным IP: [пошаговая установка Linux-сервера](SERVER.md).
Если комната должна работать при выключенном ПК хоста, VPS также подходит.

## 5. Если не получилось

| Сообщение или симптом | Следующий шаг |
| --- | --- |
| Адрес не распознан | Вставьте полное приглашение или HTTPS-адрес сервера без пути; ссылка на GitHub не подходит |
| Не удалось найти сервер по имени | Проверьте домен, DNS и интернет; запросите актуальное приглашение |
| Сервер отклонил соединение | Проверьте, запущена ли комната и верен ли порт |
| Сервер не ответил | Проверьте LAN/глобальное приглашение, firewall, проброс и CGNAT |
| Сертификат не совпадает | Запросите новое приглашение после пересоздания комнаты; не обходите проверку |
| Пароль принят, но нет голосового подключения | Проверьте голосовой сервис и TCP/UDP-порты; см. диагностику в руководстве сервера |
| Подключение есть, но звука нет | Проверьте устройства, mute/deafen, индивидуальную громкость и PTT на обоих ПК |

Инструкция соответствует 0.3.0. Формулировки зависят от выбранного языка. Подробности: [руководство](GUIDE.ru.md), [сервер](SERVER.md).

Для обращения в [GitHub Issues](https://github.com/IlyaRusskikh/voicecord/issues/new/choose)
укажите версии клиента/сервера, Windows, LAN или разные сети, шаги и точный
текст ошибки. Удалите приглашения, пароли, ключи E2EE, личные IP и записи разговоров.

Реальный разговор на двух ПК нельзя заменить синтетическими тестами.
Расширенная проверка перед выпуском: [ACCEPTANCE.md](ACCEPTANCE.md).
