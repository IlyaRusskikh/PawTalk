# Первая публикация Voicecord на GitHub

**Историческая инструкция первоначальной настройки.** Репозиторий и preview
0.1.0 уже опубликованы. Следующие выпуски: [RELEASING.md](RELEASING.md);
оформление и обнаружение проекта: [DISCOVERABILITY.ru.md](DISCOVERABILITY.ru.md).

Исходники находятся в корне проекта `voicecord`. Соседние проекты не входят
в репозиторий. Git уже инициализирован локально, основная ветка — `main`.

## Перед загрузкой

```powershell
git status --short
npm run check:public
```

Проверка анализирует файлы, не исключённые из Git, и содержимое индекса:
подозрительные ключи/токены, локальные конфигурации и слишком большие файлы.
Это эвристика, а не гарантия отсутствия секретов. Перед коммитом просмотрите
список файлов и `git diff --cached`. `.gitignore` не защищает файл, который
уже отслеживается; такая ошибка выявляется проверкой.

На компьютере остаются, но не публикуются `deploy/generated/`, `.env*` с реальной
конфигурацией, `CONTINUE.md`, сетевые отчёты, сертификаты/ключи, журналы,
`node_modules/`, сгенерированные файлы и `release/`. Для пользователей публикуются
исходники и проверенный установщик отдельным asset релиза.

## GitHub Desktop

1. **File → Add local repository**: выберите папку `voicecord`.
2. Проверьте **Changes**. Если первого коммита ещё нет, создайте
   `Initial public release 0.1.0` после проверок.
3. Если репозиторий на GitHub ещё не создан, выберите **Publish repository**,
   имя `voicecord`, снимите **Keep this code private** и опубликуйте.
4. Если на GitHub уже есть пустой `voicecord`, настройте его URL как `origin`
   через **Repository → Repository settings → Remote**, затем **Push origin**.

GitHub Desktop использует авторизацию своего аккаунта; отдельный SSH-ключ для
такого сценария не обязателен. Командный Git через SSH можно настроить отдельно.

## Командный Git через SSH

Создайте на GitHub **пустой** публичный `voicecord` без автоматически добавленных
README, `.gitignore` и LICENSE. Локальные версии этих файлов уже подготовлены.
После добавления своего **публичного** SSH-ключа на GitHub проверьте
`ssh -T git@github.com`. Приватный ключ остаётся на компьютере.

Если первого коммита ещё нет:

```sh
git add .
git diff --cached --stat
```

Просмотрите `git diff --cached`, повторите `npm run check:public`, затем:

```sh
git commit -m "Initial public release 0.1.0"
```

Подставьте свой GitHub-логин вместо `YOUR_GITHUB_LOGIN`:

```sh
git remote add origin git@github.com:YOUR_GITHUB_LOGIN/voicecord.git
git push -u origin main
```

Если `origin` уже существует, сначала проверьте `git remote -v`; при необходимости
используйте `git remote set-url origin <URL>`, а не добавляйте его повторно.
Если на GitHub уже созданы README или LICENSE, сначала получите удалённую историю
и объедините её с локальной, разрешив конфликты. Не используйте force push:
точные команды зависят от имеющейся истории.

## После загрузки

- Проверьте оба README, лицензию и вкладку Actions. Не считайте CI пройденным,
  пока GitHub не завершит его успешно.
- Включите доступные GitHub secret scanning / push protection и private
  vulnerability reporting в настройках безопасности репозитория.
- Заполните About, например `Self-hosted voice rooms for Windows`, и topics
  `voice-chat`, `self-hosted`, `electron`, `webrtc`, `livekit`.
- Выпустите `v0.1.0` по [RELEASING.md](RELEASING.md). Репозиторий с исходниками
  и GitHub Release с установщиком — отдельные этапы.
- Передавайте пользователям ссылку на конкретный релиз. Не делитесь конфигурацией
  сервера, локальными журналами и всем содержимым `release/`.

Если запускаете изменённый сервер для других пользователей, AGPL требует заметно
предложить им соответствующие исходники вашей версии. Разместите доступную им
ссылку на точные исходники на странице сервиса/в интерфейсе и сохраняйте инструкции
сборки. Секреты и персональные данные в исходники не включаются.
