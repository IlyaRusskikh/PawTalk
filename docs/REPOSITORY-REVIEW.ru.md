# Улучшения репозитория после 0.1.0

Проверено **5 ноября 2026** в локальной рабочей копии. Это предметная проверка
оформления, пути первого пользователя и выбранных ошибок подключения, а не
независимый аудит безопасности или завершённая аппаратная приёмка.

## Что подготовлено

- Согласованные README на русском и английском: назначение, точная ссылка на
  опубликованный установщик, статус preview, быстрый старт, FAQ и скриншоты.
- Три скриншота настоящего приложения в отдельном профиле: главный экран,
  создание комнаты и настройки звука. Использован синтетический микрофон.
- [Первый разговор](FIRST-CALL.ru.md): установка, SHA-256, микрофон, LAN,
  отдельная проверка интернета и разбор типичных проблем.
- В форме входа появился текст о неверном адресе и назначении LAN-приглашения;
  пробелы вокруг приглашений обрабатываются одинаково на всех этапах входа.
- Диагностика распознаёт DNS/TCP-причины, вложенные в ошибки fetch. При тайм-ауте
  указывает нужные типы портов и возможность CGNAT. Сообщения не выводят секреты
  из исходной ошибки. В форме создания автопроброс описан как попытка.
- Двуязычный статический сайт в `website/` с понятными загрузками, FAQ,
  canonical/hreflang и Open Graph. Есть локальный предпросмотр и ручной Pages
  workflow. В нём публикуется только `website/`.
- Шаблоны issues для ошибок, настройки и предложений. CI дополнен проверкой
  ссылок сайта и сценарием входа в собранном интерфейсе.

Изменения подготовлены локально. Подготовка workflow не означает его выполнение
на GitHub, публикацию сайта или изменение About/topics.

## Зависимости

На момент проверки `npm audit --omit=dev` не сообщил известных уязвимостей
в production-дереве. Полный `npm audit` сообщил **6 moderate**, **0 high/critical**
в цепочке инструментов сборки: `minimatch`, `@electron/universal`,
`app-builder-lib`, `dmg-builder`, `electron-builder` и
`electron-builder-squirrel-windows`. Это текущий ответ реестра для lockfile;
числа могут меняться без изменения исходников.

Принудительное обновление electron-builder не применялось. Обновление этой
цепочки следует делать отдельно с повторной проверкой нативного модуля,
упаковки и запуска установщика. Отсутствие известных advisories не доказывает
отсутствие уязвимостей.

## Следующие действия

1. Просмотреть diff, закоммитить и отправить изменения в репозиторий.
2. Обновить GitHub About и topics по [готовым формулировкам](DISCOVERABILITY.ru.md).
3. Включить GitHub Pages и запустить ручной workflow по
   [инструкции сайта](../website/README.md). Только после проверки опубликованного
   URL добавить его в About и отправить на индексирование.
4. Выполнить [первый звонок на двух физических ПК](FIRST-CALL.ru.md), затем
   повторить из разных сетей. Записать версии, устройства и результат без секретов.
5. Проверить чистую установку Windows и глобальный PTT в целевых играх.
6. Для следующего бинарного выпуска пройти [RELEASING.md](RELEASING.md).
   Опубликованный 0.1.0 не заменять; исправления приложения войдут в новый выпуск.

Цифровая подпись требует выбора сертификата или сервиса подписи и настройки
секретов CI владельцем. Автообновление требует отдельной реализации, проверки
подлинности обновлений и сценария восстановления. Ни подпись, ни автообновление
в этой доработке не добавлены. Честный статус сохранён в README и на сайте.
