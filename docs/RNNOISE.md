# Нейросетевое шумоподавление

В настройках звука доступны «Выключено», «Стандартное · WebRTC» и «Нейросетевое · RNNoise». Для нового профиля выбран RNNoise. Старый явно отключённый фильтр остаётся отключённым; старый включённый стандартный фильтр переходит на RNNoise. Остальные пользовательские настройки, включая ручной порог, сохраняются.

Начните с RNNoise и автоматической чувствительности. Высокий ручной порог по-прежнему способен отсечь тихую речь. Шкала показывает уровень после фильтрации; открытие дополнительно зависит от оценки речи, поэтому громкий очищенный остаток шума не обязательно откроет передачу.

## Аудиотракт

Для меньшей задержки захват/обработка микрофона и воспроизведение разговора используют общий AudioContext. Локальная проверка микрофона вне разговора имеет собственный контекст. Обычный AEC захвата включён по умолчанию; дополнительный фильтр «Подавлять голос собеседника рядом» включается отдельно, по умолчанию выключен и при включении добавляет 80 мс. Результаты оптимизации: [LATENCY.md](LATENCY.md).

Захват Windows/WebRTC с выбранными AEC и AGC → RNNoise (если выбран) → усиление → определение речи → буфер начала слова → Opus/LiveKit. В режиме RNNoise встроенное noiseSuppression захвата выключено. При смене режима выход кратковременно заглушается, ограничения захвата применяются, затем включается выбранный обработчик. Прослушивание и соединение не пересоздаются.

RNNoise работает в AudioWorklet при 48 кГц, mono, блоками по 480 сэмплов. Буфер выделен заранее. Модель загружается локально из ресурсов приложения; нет CDN, облачного API, подписки и загрузки модели во время звонка. При ошибке модель не заменяется незаметно необработанным микрофоном.

Активация голосом использует очищенный RMS и RNNoise VAD. Для открытия нужны два последовательных речевых кадра; удержание конца фразы — 300 мс, порог уверенности при удержании ниже. Буфер 20 мс сохраняет звук перед обнаружением речи. В PTT оценка речи не блокирует ручную передачу, а предыстория перед нажатием не воспроизводится. Mute очищает очереди, и в модель во время mute подаются нули.

Нейросетевой путь в режиме активации голосом имеет около 50 мс алгоритмической буферизации: формирование 10-мс кадра, 20-мс предыстория и примерно 20 мс задержки выбранной модели (определено корреляцией тестовой речи). В PTT предыстория отключена. Это не полная задержка от микрофона до наушников: устройства, браузер, Opus, сеть и jitter buffer добавляют своё время.

## Сборка и лицензии

Используется `@shiguredo/rnnoise-wasm` **2025.1.5**. `scripts/prepare-rnnoise.mjs` извлекает встроенный WASM из закреплённого пакета без изменения байтов, проверяет WebAssembly и SHA-256 и создаёт `src/generated/rnnoise.wasm`. `npm run dev`, `npm run dev:web` и `npm run build` выполняют этот шаг автоматически. Сгенерированный файл исключён из Git, Vite включает его в dist, electron-builder — в ASAR. Стабильный C ABI вызывается собственным адаптером без DOM-полифиллов и браузерной обёртки на аудиопотоке.

`THIRD_PARTY_NOTICES.md` и тексты BSD/Apache включены в приложение. Изменения модели или зависимостей требуют повторного аудиотеста и осознанного обновления проверяемого хеша.

## Проверки

- Unit: настоящий WASM подавляет детерминированные щелчки более чем на 12 dB без участия gate; проверены VAD, сохранение тихого начала, mute и отсутствие воспроизведения предыстории PTT.
- Electron: загрузка из file:// с CSP, живая шкала и прослушивание, смена трёх режимов без остановки проверки.
- Два клиента через локальный Go/LiveKit: синтезированная тихая речь с добавленными щелчками, ненулевая декодированная речь, открытие нейросетевого VAD, отсутствие второго шумоподавителя, mute/PTT и повторный вход.
- `scripts/neural-quality.mjs speech.wav`: необязательная проверка на 48 kHz mono PCM16 WAV. Скрипт ослабляет голос на 12 dB, добавляет искусственные щелчки и фон; сохраняет вход, выход и метрики в `release/qa/`. Проверяет сохранность речевой формы, а не субъективное сходство с Krisp.

Тестовая речь создана Windows SpeechSynthesizer, пользовательский микрофон не записывался. Результат синтетических тестов не гарантирует такое же подавление любой реальной клавиатуры. Реальные устройства, тихие согласные, одновременная печать и игровая нагрузка проверяются пользователем отдельно.
