# Permanent Windows server / Постоянный Windows-сервер

**Server 0.10.1 / Manager 0.2.0 — released previews / предварительные выпуски.**
[Установщик Manager 0.2.0](https://github.com/IlyaRusskikh/PawTalk/releases/download/manager-v0.2.0/PawTalk.Server.Manager.Setup.0.2.0.exe) · [Изменения](RELEASE-NOTES-0.10.0.md).
Целевые ОС: Windows 10/11 x64 и Windows Server 2019/2022/2025 x64.
Это матрица целей, а не утверждение о проверке всех этих ОС.
На локальной машине проверяется настоящий Go/LiveKit, SQLite, Ed25519 и Windows
job lifecycle. Регистрация SCM, LocalService ACL и автозапуск проверяются отдельным
Windows CI-тестом на Windows Server 2022 и 2025: службы, EXE-установка и удаление
с сохранением данных прошли. Windows 10/11 и Server 2019 отдельно не проверялись.
Реальный внешний TCP/UDP и голос между физическими устройствами не проверены.

## Установка

Скачайте `PawTalk.Server.Manager.Setup.0.2.0.exe` из `manager-v0.2.0`.
Запустите EXE с правами администратора, выберите язык и заполните настройки:
публичный IPv4, порт, шифрование, SHA-256 key ID (не секретный ключ), лимит истории
и общий переключатель автообновления сервера/Manager. Шифрование и обновления
по умолчанию включены. Отдельная страница в конце установки показывает приглашение
с паролем в `#password=…` и кнопку копирования. Не публикуйте эту ссылку.
При включённом E2EE секретный ключ участников передаётся отдельно; key ID из мастера
не заменяет его. Клиент подставляет пароль из ссылки и при необходимости просит ключ E2EE.
Пароль комнаты, отпечаток сертификата TLS в пути приглашения и секретный ключ E2EE —
разные значения. Сервер генерирует пароль и TLS-сертификат, но не секрет E2EE.
Клиент вычисляет SHA-256 введённого E2EE-секрета и передаёт серверу только key ID;
сервер сравнивает его с настройкой. Получить секрет из отпечатка невозможно.
Для LAN и loopback клиент сохраняет голосовой `/rtc` на том же проверенном HTTPS-адресе,
не перенаправляя соединение на публичный IP из ответа standalone-сервера.
Повторная установка пропускает форму при найденном конфиге и сохраняет комнату,
настройки и приглашение. Пароль не меняется автоматически.
Приглашение показывается только на странице мастера: вывод служебного процесса
перехватывается без отдельного окна консоли и без записи пароля в детали установки.
При повторной установке EXE службы временно останавливаются для замены bootstrap
runtime/host; это прерывает звонок. Обычное обновление кода Manager сервер не останавливает.

Python встроен в установщик. Docker, WSL, Node.js и отдельная установка Python
не требуются. Настоящие подписанные Server/Manager релизы и заранее настроенные
корни доверия обязательны. Публичные ключи в `manager/trust.json` настроены;
подписанные релизы опубликованы, как и для Linux.

По умолчанию программа находится в `%ProgramData%\PawTalk Server Manager`,
данные/конфигурация/backup — в `%ProgramData%\PawTalk`.
Каталог служб должен быть непосредственным дочерним каталогом настоящего
системного ProgramData; произвольный пользовательский Temp/Desktop не принимается.
Папка программы фиксирована в защищённом общем ProgramData, а не пользовательском
AppData. Она создаётся сразу с владельцем Administrators и закрытыми правами записи:
служба не исполняет пользовательский изменяемый код от LocalSystem.
При переходе с прежнего Program Files установщик перерегистрирует службы с новым
путём, сохраняет каталог комнаты и после успеха удаляет прежние файлы программы.
Службы `PawTalkServer-<root hash>` и `PawTalkManager-<root hash>` запускаются
автоматически. Server использует LocalService; Manager — LocalSystem для
управления службами и защищёнными файлами. Обычные пользователи не могут менять
код, конфигурацию и архивы. LocalService может читать код/конфигурацию и изменять
только каталоги данных сервера и его логов.

Нужны входящие TCP `PORT`, TCP `PORT+1`, UDP `PORT+2` (18443/18444/18445).
`PORT+3` — только loopback. Установщик не меняет Windows Firewall, роутер и правила
провайдера; настройте эти входящие порты сами. При CGNAT одной установки EXE
недостаточно для связи извне. Арендовать VPS необязательно: подходит свой постоянно
работающий компьютер с доступным IP и портами.

## Обслуживание

Через **Настройки сервера…** в меню трея (или Configure в меню «Пуск») открывается
графическое окно с заполненными текущими значениями: IPv4, основной порт, E2EE,
SHA-256 key ID, лимит истории, автообновления Server и Manager, язык Manager.
Открытие требует прав администратора. Закрытие без применения ничего не меняет.
Одно окно не перезаписывает настройки, изменённые после его открытия.
Изменения автообновлений и языка не перезапускают сервер. Сетевые параметры, E2EE
и лимит истории применяются через согласованную резервную копию и проверенный
перезапуск; при неудаче восстанавливаются прежняя конфигурация и данные.
После смены IP или порта нужно скопировать новое приглашение и проверить
проброс портов/брандмауэр. При смене IP сервер перевыпускает TLS-сертификат,
сохраняя пароль и историю; старый отпечаток больше не подходит. Это требует
нового Server с командой `serve rebind`; старый подписанный Server отклонит
операцию, после чего Manager выполнит откат. Изменение порта поддерживается
существующим native Server. Настройки Linux/Compose этой формой не меняются.

Ярлык **PawTalk Server** открывает значок с маленьким сервером в правом верхнем углу в трее. Меню включает и отключает
сервер, копирует приглашение с паролем и позволяет явно сменить забытый пароль.
**Остановить сервер и выйти** останавливает сервер; **Закрыть значок** оставляет
службу работать. Установщик предлагает ярлык на рабочем столе и показ значка при входе.
Ярлыки **Status** и **Configure** в меню Пуск запрашивают повышение прав.
Переустановка Manager сохраняет уже установленный Server. Для защиты активности
нужен Server 0.10.1; после обновления EXE выполните `update now` из списка ниже.
Откройте PowerShell от администратора:

```powershell
$ctl = "$env:ProgramData\PawTalk Server Manager\pawtalkctl.exe"
& $ctl status
& $ctl doctor
& $ctl setup
& $ctl configure PAWTALK_CHAT_MAX_MB=256 --yes
& $ctl update check
& $ctl update now
& $ctl manager check
& $ctl manager now
& $ctl backup create
& $ctl backup list
& $ctl backup restore backup-012345abcdef --yes
& $ctl logs
& $ctl invitation --url
# Явная смена пароля прерывает звонки и делает прежние ссылки с паролем недействительными.
& $ctl invitation --reset-password
& $ctl uninstall --keep-data --yes
```

Имя backup — пример. CLI `uninstall --keep-data --yes` останавливает службы и
сохраняет файлы для восстановления. EXE `Uninstall.exe` удаляет службы и файлы
программы; отдельный чекбокс **Удалить настройки и данные** также удаляет историю,
сертификаты, пароль и резервные копии. По умолчанию чекбокс выключен. Для полного
silent-удаления используется `/S /DELETE-DATA`. Пути и метки владения проверяются
перед рекурсивным удалением; ссылки/junction отклоняются.

Windows-копия пароля хранится в приватном каталоге Manager в зашифрованном Windows
DPAPI виде для той же учётной записи Windows и связана с текущим хэшем пароля сервера.
Другой администратор может явно сменить пароль, но не расшифровать чужую копию.
На старой установке, где пароль
уже был выдан одноразово, его нельзя восстановить из серверного хэша: используйте
явную смену пароля через трей. Восстановленная старая копия или внешний сброс пароля
не приводят к выдаче устаревшего сохранённого пароля. E2EE-ключ сервер не сохраняет.
Для восстановления в новой директории сначала выполните `status` с выбранным
`--root`, чтобы создать защищённую структуру; затем скопируйте туда полный backup
в `var\backups\pawtalk` и выполните `backup restore`. Чужая непустая директория
без метки владения не принимается; ссылки/junction внутри managed root запрещены.

## Общая логика с Linux

В следующей сборке Server `/api/presence` и `/api/preview` требуют токен текущего
доступа к комнате. Без него не возвращаются ни число, ни имена, ни непрочитанное.
Авторизация проверяется до обращения к общему кэшу счётчика. Токены чата и
предпросмотра привязаны к текущему паролю и политике E2EE. Штатная смена пароля
также меняет секрет подписи LiveKit, сохраняя сертификат и идентичность комнаты.
Старые голосовые токены после перезапуска перестают приниматься. Сам общий
секрет E2EE при смене пароля не меняется.

Клиент не использует токен активной комнаты для проверки другой закладки и не
запрашивает публичный счётчик при отказе в доступе. Устаревшая закладка показывает
«Требуется повторный вход» без данных об активности. После успешного входа с
новым паролем закладка той же проверенной комнаты обновляет сохранённые данные
доступа; отдельная копия для каждого пароля не создаётся.

Обновление одного Client скрывает небезопасный публичный fallback, но запрет
публичного счётчика для всех клиентов и отзыв голосовых токенов требуют нового
подписанного выпуска Server. Пересборка Manager не заменяет установленный Server
произвольным ZIP: проверка подписанного манифеста сохраняется.

Обе ОС используют `manager/pawtalk_manager/controller.py`: lock, транзакционный
журнал, остановленная согласованная копия, проверка здоровья/TLS identity,
восстановление пары «версия сервера + данные» при ошибке и защита от downgrade.
На Linux runtime — Docker Compose, на Windows — нативные Go/LiveKit EXE и SCM.
Это одинаковое серверное ядро из исходников `server/`, а не Linux Docker-образ
внутри Windows. Временные комнаты клиента по-прежнему используют свой pin.

Сервер проверяется по `server-v*`, Manager — по `manager-v*`; канала выбора нет.
Manager обновляет свой проверенный общий bundle без перезапуска сервера.
Установленный Python runtime и минимальный Go SCM launcher относятся к стабильному
bootstrap protocol 1; их замена требует повторной установки Manager EXE. Windows-мастер
установки и выдача приглашений выполняются из bootstrap, поставляемого этим EXE;
обычное обслуживание продолжает использовать выбранный подписанный Manager bundle. Это
отдельно от автоматического обновления Python-кода Manager. Linux также не
обновляет системный Python и стабильный launcher через bundle.

Backup предназначен для восстановления на той же ОС. Межплатформенный перенос
Linux ↔ Windows не заявлен: у ОС разные runtime receipts и пути хранения.

## Сборка и проверки

```powershell
npm run server:prepare
node scripts/build-windows-server.mjs
node scripts/build-manager-windows.mjs
node scripts/windows-manager-smoke.mjs
# Администратор: реальные SCM-службы с отдельными именами и временными данными.
node scripts/windows-manager-smoke.mjs --scm
# CI / чистая тестовая Windows: настоящий silent EXE и uninstaller.
node scripts/windows-manager-smoke.mjs --scm --installer
```

Сборка ничего не публикует. В smoke используются временные ключи и локальные
архивы; production origin и подписи проверяются отдельными контрактными тестами.
Без `--scm` проверяется тот же сервисный цикл через консольный host/job, но не SCM.
`--scm` требует администратора и не подменяет отсутствие прав успешным skip.
`--installer` требует чистой машины без установленного Server Manager, временно
устанавливает продукт в Program Files и проверяет настоящий uninstaller. При
существующей программе, ярлыках или регистрации этот тест отказывается их менять.
Тестовые службы используют отдельные каталоги ProgramData; их пути проверяются
перед очисткой. Jobs Windows Server 2022/2025 запускают оба режима установки.

## English

The Windows installer targets Windows 10/11 and Server 2019/2022/2025
x64. It bundles Python and needs no Docker/WSL/Node installation. These OS targets
still require actual OS-specific verification.
Windows Server 2022/2025 CI passed actual SCM service and EXE install/uninstall
checks; Windows 10/11 and Server 2019 remain unverified. Run the EXE as Administrator and
configure IP, ports, E2EE key ID, history and automatic updates. Save the invitation
and one-time password shown at the end. Configure external TCP/UDP and Windows
Firewall yourself. The same Manager controller handles signatures, backup,
transactions, rollback and updates on both OSes; only runtime/service adapters
differ. Windows uses native Go/LiveKit executables, not the Linux Docker image.
Use the commands above from elevated PowerShell or the Start-menu shortcuts.
The stable bootstrap runtime/SCM host is serviced by reinstalling the Manager EXE;
automatic Manager bundle updates replace its shared Python policy code.
Uninstall retains tools, config, data and backups. Cross-OS backup migration and
real-device external-network verification are not claimed.
