# Контракт API 2

[English](api.en.md) · [Индекс](README.ru.md)

Опубликованный API 2 — **несовместимое изменение протокола**. Client проверяет версию API и необходимые возможности сервера до доказательств членства/аутентификации; скрытого перехода на API 1 нет. Server и Manager требуют соответствия API/data schema 2 при установке, обновлении и восстановлении.

## Идентичность и авторизация

Каждое устройство Client имеет собственную подписывающую идентичность и членство в конкретном сервере. Подписанные challenge связывают аутентификацию с сервером и одноразовостью; сессии и роли ограничивают операции участников, каналов, приглашений и голоса. Связь устройств — отдельный подтверждаемый протокол внутри одного сервера, а не глобальный аккаунт.

## Вступление

Первичная настройка постоянного Server: начальная ссылка хоста для администратора, одна попытка в течение 24 часов; первый клиент создаёт и сохраняет E2EE root. Обычная ссылка: администратор/модератор выдаёт одноразовый доступ (24 ч) или многоразовый (1 ч) и зашифрованный пакет root. Вступление проходит резервирование, расшифровку/проверку и подтверждение; ключ открытия пакета остаётся во фрагменте URL, а не уходит в HTTP. Отзыв/истечение запрещают **новое** вступление, но не удаляют имеющихся участников.

## Семейства endpoint и состояние

Реализация содержит обнаружение протокола/версии; challenge устройств и подписанные доказательства; двухфазные приглашения; членство/роли/модерацию; CRUD/порядок каналов; сообщения, редактирование и вложения; связь устройств; voice grants и присутствие. Ошибки различают несовместимый протокол, отказ прав, истёкшую ссылку и ошибки соединения. HTTP health не равен успешному голосу.
