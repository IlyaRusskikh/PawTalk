# Безопасность и границы E2EE

[English](security.en.md) · [Индекс](README.ru.md)

API 2 требует сквозного шифрования **голоса, сообщений и изображений**; TLS и E2EE решают разные задачи.

| Механизм | Защищает | Не гарантирует |
| --- | --- | --- |
| TLS + отпечаток приглашения | Проверенный транспорт до нужного сервера | Секретность служебных метаданных сервера |
| Подписанная идентичность устройства | Владение ключом и свежесть доказательств | Права без актуального членства |
| Временные приглашения и роли | Вступление и новые операции API | Удаление уже полученного контента |
| E2EE | Содержимое от Go API/LiveKit Server | IP, время, размеры, метаданные участников/каналов |

Первый авторизованный Client создаёт случайный 256-битный корень сервера, сохраняет его в защищённом хранилище ОС и выдаёт шифрованные пакеты для приглашений. Согласование ключей и вывод ключей каналов/назначений используют криптографические контексты с ID сервера/канала. Текст/вложения защищены AES-256-GCM, голос — E2EE SDK LiveKit; связь устройств требует подтверждаемого аутентифицированного обмена. Client root и закрытые ключи подписи не входят в Server backup.

**Критические ограничения:** все участники одного сервера разделяют root; разделение по каналам контекстное, а **не отдельные секретные каналы**. Выход, кик/бан, отвязка и истечение приглашения не меняют root и не отзывают полученные ключи/копии. Не заявлены forward secrecy, восстановление утраченного root и криптографическое стирание. Уже выданные media grants могут повторно использоваться ограниченное время. Сервер видит метаданные; компрометация конечного устройства раскрывает его ключи.

**Доверие к артефактам** отдельно от E2EE: подписанные манифесты, хеши и immutable digest защищают поставку, а не секретность чата. [Уязвимости](../SECURITY.ru.md) · [API](api.ru.md).
