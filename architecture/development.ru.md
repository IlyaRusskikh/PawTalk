# Разработка и сборка

[English](development.en.md) · [Индекс](README.ru.md)

Работающий код из `main` **не доказывает** доступность функции в опубликованном теге. Перед изменениями прочитайте [AGENTS.md](../AGENTS.md) и [правила агентов](../agents/README.md). Работайте в отдельной ветке, без прямого push в `main`. Для сборки Desktop нужны **Windows x64**, Node.js 24.22.1+, Go 1.27.3+ и Visual Studio Build Tools с C++/Windows SDK. `PAWTALK_GO` может указывать на исполняемый Go.

~~~powershell
npm ci
npm run native:build
npm run dev
~~~

Зоны ответственности: Client [React/TypeScript](../src/), [Electron](../electron/); общее ядро Server [Go](../server/); Windows Manager [Go controller](../manager/windows/) и [Electron UI](../manager/desktop/); Linux Manager [Python](../manager/pawtalk_manager/). Сетевое поведение проверяется контрактными, релизными и security-тестами, а не только локальным GUI.

Доступные проверки находятся в [package scripts](../package.json), [Go tests](../server/) и [CI](../.github/workflows/check.yml). Выбирайте тесты по затронутым компонентам и [правилам](../agents/testing/README.md). Не коммитьте сгенерированные assets, закрытые ключи, ссылки входа, локальные backup и отчёты диагностики.

**Важно:** актуальный исходный код и исторические harnesses могут отличаться от опубликованных бинарников API 2. Пользовательские документы сверяйте с неизменяемыми релизами/asset, а не только с новым `main`.

## Отдельный Server для review в Windows

Команда **npm run review:server** собирает текущее общее Go-ядро и запускает постоянный сервер разработки с отдельным LiveKit. Установленный Manager, служба Windows и Docker не нужны. Нужен закрепленный Go toolchain (поддерживается PAWTALK_GO); инструменты C++ для native-модуля Client этой команде не нужны. При первом запуске LiveKit подготавливается существующим механизмом проверенной загрузки.

По умолчанию в ссылках используется 127.0.0.1, группа портов — 28443–28446, отдельно от стандартных портов установленного сервера. Обычные серверные listeners слушают интерфейсы хоста: localhost в ссылке не заменяет firewall. Для другого устройства используйте **npm run review:server -- --ip 192.168.1.10**, указав LAN-адрес этого компьютера; при необходимости разрешите группу портов в firewall. Автоматически правила firewall не меняются.

Данные находятся в release/review-server/data; бинарники и приватный файл первого администратора initial-admin.txt — в той же игнорируемой папке review. В другом терминале запустите **npm run review** и вставьте содержимое файла в «Присоединиться». После первого вступления обычные приглашения создаются в Client. Перезапуск сохраняет идентичность, историю и участников и удаляет устаревший файл первого администратора. Остановка: Ctrl+C либо **npm run review:server -- --stop**; данные сохраняются.

**--profile NAME** задает независимый сервер, **--port PORT** — свободную группу из четырех портов; при остановке укажите тот же профиль. При перезапуске повторяйте нестандартные IP/порт. Для смены объявленного IP используйте новый профиль вместо замены сохраненной идентичности. Каждый запуск пересобирает исходники; повторный запуск работающего профиля отклоняется. Для новых изменений остановите сервер и запустите снова. Данные установленного Manager/Server не используются. Это исходный код разработки, не подписанный релиз.

Проверка: **node scripts/review-server-smoke.mjs** собирает/запускает настоящий native Server, подключается с проверкой TLS-pin, отправляет шифрованный чат, останавливает/перезапускает с сохранением идентичности/истории и проверяет блокировку профиля. Синтетический профиль затем удаляется.
