# Разработка и сборка

[English](development.en.md) · [Индекс](README.ru.md)

Работающий код из `main` **не доказывает** доступность функции в опубликованном теге. Перед изменениями прочитайте [AGENTS.md](../AGENTS.md) и [правила агентов](../agents/README.md). Работайте в отдельной ветке, без прямого push в `main`. Для сборки Desktop нужны **Windows x64**, Node.js 24.22.1+, Go 1.27.3+ и Visual Studio Build Tools с C++/Windows SDK. `PAWTALK_GO` может указывать на исполняемый Go.

~~~powershell
npm ci
npm run native:build
npm run dev
~~~

Зоны ответственности: Client [React/TypeScript](../apps/client/windows/src), [Electron](../apps/client/windows/electron); общее ядро Server [Go](../apps/server); Windows Manager [Go controller](../apps/manager/windows/service) и [Electron UI](../apps/manager/windows/desktop); Linux Manager [Python](../apps/manager/linux/pawtalk_manager). Сетевое поведение проверяется контрактными, релизными и security-тестами, а не только локальным GUI.

Доступные проверки находятся в [package scripts](../package.json), [Go tests](../apps/server) и [CI](../.github/workflows/check.yml). Выбирайте тесты по затронутым компонентам и [правилам](../agents/testing/README.md). Не коммитьте сгенерированные assets, закрытые ключи, ссылки входа, локальные backup и отчёты диагностики.

**Важно:** актуальный исходный код и исторические harnesses могут отличаться от опубликованных бинарников API 2. Пользовательские документы сверяйте с неизменяемыми релизами/asset, а не только с новым `main`.

## Отдельный Server для review в Windows

Команда **npm run review:server** собирает текущее общее Go-ядро и запускает постоянный сервер разработки с отдельным LiveKit. Установленный Manager, служба Windows и Docker не нужны. Нужен закрепленный Go toolchain (поддерживается PAWTALK_GO); инструменты C++ для native-модуля Client этой команде не нужны. При первом запуске LiveKit подготавливается существующим механизмом проверенной загрузки.

По умолчанию в ссылках используется 127.0.0.1, группа портов — 28443–28446, отдельно от стандартных портов установленного сервера. Обычные серверные listeners слушают интерфейсы хоста: localhost в ссылке не заменяет firewall. Для другого устройства используйте **npm run review:server -- --ip 192.168.1.10**, указав LAN-адрес этого компьютера; при необходимости разрешите группу портов в firewall. Автоматически правила firewall не меняются.

Данные находятся в release/review-server/data; бинарники и приватный файл первого администратора initial-admin.txt — в той же игнорируемой папке review. В другом терминале запустите **npm run review** и вставьте содержимое файла в «Присоединиться». После первого вступления обычные приглашения создаются в Client. Перезапуск сохраняет идентичность, историю и участников и удаляет устаревший файл первого администратора. Остановка: Ctrl+C либо **npm run review:server -- --stop**; данные сохраняются.

**--profile NAME** задает независимый сервер, **--port PORT** — свободную группу из четырех портов; при остановке укажите тот же профиль. При перезапуске повторяйте нестандартные IP/порт. Для смены объявленного IP используйте новый профиль вместо замены сохраненной идентичности. Каждый запуск пересобирает исходники; повторный запуск работающего профиля отклоняется. Для новых изменений остановите сервер и запустите снова. Данные установленного Manager/Server не используются. Это исходный код разработки, не подписанный релиз.

Проверка: **node scripts/review-server-smoke.mjs** собирает/запускает настоящий native Server, подключается с проверкой TLS-pin, отправляет шифрованный чат, останавливает/перезапускает с сохранением идентичности/истории и проверяет блокировку профиля. Синтетический профиль затем удаляется.

## Команды Make для review в Windows

Установите GNU Make (например, winget install --id ezwinports.make --exact --source winget --scope user), затем откройте терминал заново для обновления PATH. Вызывайте make из корня репозитория; без аргументов выводится справка. Прежние make installer и make all по-прежнему собирают установщик.

- make client-start / make client-stop: сборка текущего интерфейса Client и запуск/полное завершение отдельного review-профиля. Обычный крестик окна сохраняет поведение скрытия в трей. Остановка обращается только к экземпляру этого launcher, а не ко всем процессам с похожим именем.
- `make client-start-first`, `make client-start-second`, `make client-start-third`: одновременная работа независимых экземпляров Client. Остановка каждого — `make client-stop-first`, `make client-stop-second` или `make client-stop-third`. Каждому имени соответствуют собственные постоянный профиль и логи; команды эквивалентны `make client-start PROFILE=first` / `make client-stop PROFILE=first`. Можно использовать и другие имена профилей. Запускайте экземпляры последовательно, чтобы их сборки не пересекались. `make stop` без `PROFILE` останавливает только экземпляр по умолчанию.
- make manager-start / make manager-stop: сборка текущего интерфейса Manager и запуск/завершение отдельного профиля UI. Если Manager установлен и найден по его записи реестра, используются его backend и корень данных; действия управляют этим установленным сервером и могут запросить обычное разрешение UAC. Иначе используется подготовленный локальный runtime Manager. Это review интерфейса, а не отдельная установка сервера. Остановка UI сохраняет службы Server и отказывается прерывать занятую операцию Manager.
- make server-start / make server-stop: существующий native review Server; запуск остается в текущем терминале. SERVER_IP, SERVER_PORT и SERVER_PROFILE задают настройки этого отдельного сервера.
- make stop: остановка выбранных Client, UI Manager и review-сервера. PROFILE=name выбирает другой профиль Client/Manager UI. Состояние и логи находятся в release/review-apps и игнорируются Git.

Launcher использует аутентифицированные локальные pipes и корректное завершение приложений; принудительного завершения по имени процесса и установки новых служб нет. Повторный запуск безопасен, повторная остановка успешна. Проверка окон: node tooling/dev/review-app-smoke.mjs; в ней привилегированный broker Manager синтетически отклоняет запросы, вместо повышения прав и изменения настоящего хоста.

Новые профили review Server запускаются на API 3. Для входа используйте приватное приглашение владельца из файла, путь к которому показывает launcher. При запуске ранее инициализированного профиля API 2 Server сохраняет `api2-before-migration.tar` в каталоге данных и ждёт владельца на том же адресе. Откройте сервер в review-профиле Client, которому он принадлежит, выберите **Перенос сервера на API 3** и подтвердите действие. Client подготовит историю с помощью локального ключа и подпишет переключение. Server откроет API 3 без дополнительной команды. Сохраните комплект восстановления из Client в приватном месте.
