# Сеть и транспортные границы

[English](networking.en.md) · [Индекс](README.ru.md)

PawTalk разделяет HTTPS/API сигнализацию и медиа LiveKit. Выбранный базовый порт (`PORT`, обычно **18443**) задаёт четыре listener:

| Listener | Назначение | Доступ |
| --- | --- | --- |
| TCP `PORT` | HTTPS/API и сигнализация | Пользователи |
| TCP `PORT+1` | Медиа по TCP | Пользователи |
| UDP `PORT+2` | Медиа по UDP | Пользователи |
| TCP `PORT+3` | Внутреннее управление медиа | Только loopback |

Linux Manager запускает Docker Compose с `network_mode: host`, а не вручную созданный Swarm/Caddy. Постоянный Windows Server — нативная служба под управлением Manager; временный Server живёт внутри Client. TCP/UDP, брандмауэр/маршрутизация и фиксированный IPv4 должны согласовываться между хостом и внешней сетью.

Приглашения содержат адрес хоста, TLS-отпечаток и секретный фрагмент для открытия пакета ключей. Фрагмент остаётся у клиента, а не становится HTTP-ключом. Сохранённый адрес в Client может быть LAN IP; при отсутствии NAT loopback внешним участникам нужна правильно отредактированная ссылка с внешним IP, но тем же отпечатком/фрагментом.

Ответ HTTP `/healthz` не проверяет UDP или физический звук. Для уверенности нужен реальный звонок Client-to-Client из разных сетей. [Пользовательская инструкция](../docs/server/networking.ru.md).
