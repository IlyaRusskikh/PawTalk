# Проверки и границы подтверждений

[English](verification.en.md) · [Индекс](README.ru.md)

PawTalk использует несколько уровней проверок; они **не взаимозаменяемы**.

| Уровень | Что подтверждает | Чего не подтверждает |
| --- | --- | --- |
| Типы/unit/security | Локальная логика, отказ несовместимого протокола, криптографическое оформление и ошибки | Реальные устройства, доступность WAN, работа служб ОС |
| API/integration harness | Членство, каналы, приглашения, сохранение сообщений и ожидаемые Server взаимодействия | Физический микрофон/PTT/игры |
| Docker/Compose lifecycle | Здоровье контейнера, обновления/restore, тома и конфигурацию Linux | Настоящую загрузку systemd хоста, UDP роутера/провайдера |
| Тесты службы/установки Windows | SCM/UAC и службу в проверенных образах CI | Каждую Windows-систему или внешнюю сеть |
| Проверка опубликованных релизов | Подписанные байты, хеши, описания и совместимость тегов | Гарантию пользовательского опыта |

Опубликованный API 2 preview покрывается синтетическими и CI-тестами, но **настоящие устройства, удалённые TCP/UDP, качество/задержку звука и PTT в играх нужно фиксировать отдельно**. Успех проверки `main` не меняет задним числом опубликованный тег.

При изменении документов сверяйте утверждения с release notes и тестами; сохраняйте ограничения, различайте целевые и проверенные платформы. После изменения релизных описаний выполните `node scripts/check-release-notes.mjs` и связанные тесты; для сайта — `node scripts/check-website.mjs`. См. [правила тестов](../agents/testing/README.md) и [CI](../.github/workflows/check.yml).
