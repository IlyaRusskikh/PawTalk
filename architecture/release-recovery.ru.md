# Исправление текста уже опубликованного Release

[English](release-recovery.en.md) · [Процесс выпуска](releasing.ru.md)

Это **обслуживание только текста**, а не новый релиз, сборка, повторный tag CI или разрешение переписывать историю. Выполняйте лишь с отдельным разрешением владельца после проверки конкретного опубликованного тега.

1. Сравните снимок `releases/<tag>.md` с фактическим описанием GitHub Release и определите необходимое исправление. Не меняйте исходники неизменяемого тега, бинарники, манифесты, образы и ключи подписей.
2. Измените только согласованный текст и соответствующие человеческие `.en.md`/`.ru.md` страницы. Сохраните правдивые название, канал, ссылки загрузок и исторические события.
3. Запустите `node tooling/ci/check-release-notes.mjs <tag>` и тесты. Проверьте точные ссылки на компонент/версию и отсутствие временных утверждений о CI.
4. Отдельно зафиксируйте исходные метаданные Release (`draft`, `prerelease`, `published_at`, ID/размер/digest артефактов), не публикуя чувствительные данные.
5. После явного согласования примените только текст командой `gh release edit <tag> --repo IlyaRusskikh/PawTalk --notes-file releases/<tag>.md`. Загрузите Release заново и убедитесь, что другие метаданные и артефакты не менялись.
6. Запустите `node tooling/ci/check-release-notes.mjs --published <tag>`. При несовпадении остановитесь и разберитесь, а не повторяйте автоматически.

Историческое публичное описание может отличаться от текста внутри неизменяемого source-тега. Никогда не переписывайте теги, не заменяйте установщики и не выдавайте будущие проверки за уже пройденные.
