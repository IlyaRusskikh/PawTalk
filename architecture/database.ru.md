# Модель данных и хранение

[English](database.en.md) · [Индекс](README.ru.md)

API 2 использует **SQLite STRICT schema 2** на постоянных серверах. Полный DDL (столбцы, внешние ключи, проверки, индексы, триггеры) находится в [`server/membership.sql`](../server/membership.sql). Файл членства — `membership-v2.sqlite`, локальная TLS/media-конфигурация runtime — `state.json`. Временный selfhost внутри Client держит членство и чат в памяти.

Основные логические сущности: локальные для сервера идентичности устройств и участников, роли/баны, резервирования приглашений и пакеты ключей, связанные устройства, текстовые/голосовые каналы, шифрованные сообщения/редактирования и вложения. Идентификаторы сервера и каналов участвуют в контекстах шифрования. Локальное состояние прочитанного и настройки интерфейса могут храниться отдельно от серверной БД.

**Без миграции:** старый `chat.sqlite` API 1 или исторический backup нельзя открывать как schema 2. Обновления и restore Manager проверяют схему и подписанные квитанции перед заменой состояния. Серверные резервные копии содержат зашифрованный контент и идентичности, но не корневые ключи из Client.

**Надёжность:** контроллер Server выполняет обновления и восстановление с backup/rollback, прерывая звонки. Не удаляйте журналы транзакций или тома для исправления сбоев. См. [Linux](../docs/manager/linux/maintenance.ru.md) и [Windows](../docs/manager/windows/maintenance.ru.md).
