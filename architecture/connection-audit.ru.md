## Контракт и ограничения потока

API/data schema остаются равными 2. Необязательная server-events-v1 добавляет GET /api/v2/events и GET /api/v2/events/status; chat-events-v1 с endpoint выбранного канала сохраняется для прежних сборок. Этот поток передает только метаданные без сообщений и ключей; отдельный поток зашифрованных пакетов описан ниже. Bearer остается в main; существующий мост проверяет TLS до передачи заголовков. Server проверяет членство перед ограниченными пачками и каждые 15 с. Client обнаруживает отсутствие входящего трафика, переподключается с задержкой/разбросом и догружает состояние. Старые/отключенные участники используют опрос.

События объединяются по каналу; очередь подписчика ограничена 64 ключами, при переполнении передается resync. Кадры ограничены 2048 байтами; соблюдается обратное давление получателя. Не более двух подписок на устройство и 8192 всего — это защита ресурсов, а не обещание вместимости. Истечение присутствия проверяется один раз на сервер, без отдельного таймера опроса каждого подписчика. Анонимность и скрытые результаты опросов по-прежнему защищены аутентифицированным HTTP.

Рабочий простаивающий Client не перечитывает полное состояние и каждую карточку. Сверки номера, явные команды, реальные изменения и независимая голосовая аренда создают трафик. Полные снимки профилей/состава остаются возможной нагрузкой при массовых изменениях; SQLite по-прежнему использует одно соединение. Неограниченная производительность не заявляется.

## Граница проверки

Опциональный TestServerEventFanoutLoad создает тестовых участников, открывает 100/500/1000 настоящих локальных TCP WebSocket, рассылает общее событие и читает историю с аутентификацией от каждого участника. Запуск: PAWTALK_EVENT_LOAD=1 и go test -run TestServerEventFanoutLoad -v -count=1 в server/. Тест не включает TLS, расшифровку E2EE, внешнюю сеть и звук. Это проверка рассылки, а не расчет производственного сервера или длительная нагрузочная приемка. Отдельные тесты Electron покрывают настоящий закрепленный TLS, защищенные ОС ключи, переподключение/догрузку, кеш и интеграцию аудио. Для Docker/Linux и физических устройств нужны отдельные среды.

Пример финального локального запуска (миллисекунды; время меняется):

| Участники | WS-событие p95 | Событие и чтение истории p95 | Максимум до чтения истории |
| --- | ---: | ---: | ---: |
| 100 | 175 | 187 | 189 |
| 500 | 549 | 603 | 617 |
| 1000 | 980 | 1096 | 1128 |

Это локальная пачка, а не длительная приемка потока или рекомендация оборудования. Повторные запуски на том же компьютере различались; при 1000 участниках видна стоимость последовательной аутентификации/истории.

## Доставка зашифрованных сообщений, 2026-11-18

Необязательная message-events-v1 добавляет /api/v2/events/messages. Прежний /events остается потоком метаданных с пределом 2048 байт; для пакетов сообщений предел события — 60000 байт. Запись собирает пакеты и ревизии канала до/после изменения внутри транзакции. Коммит публикует общий закодированный снимок; откат ничего не публикует и освобождает планы доставки. Правки сохраняют автора/request ID/контекст ключа; удаления передают ID и метаданные автора, завершение опроса — системный итог и защищенный оригинал. Удаление по квоте идет тем же путем. Server по-прежнему проверяет каждого подписчика перед выдачей.

Получатель расшифровывает данные прежним декодером main process. Строки, цитаты, непрочитанное и упоминания обновляются из пакета; дубли не добавляют строки/счетчики. Перед HTTP-восстановлением пропуска есть короткое окно переупорядочивания. Начальная/старая история, отсутствующие цитаты, изображения и восстановление после обрыва/resync остаются на HTTP. Очередь подписчика ограничена 64 событиями и 256 КиБ; при переполнении отправляется resync, а память не растет бесконечно. Чтение бюллетеней сохраняет персональные HTTP-проверки приватности и обновляется только по событиям нужного опроса.

Нативный тест подтверждает ноль HTTP-чтений истории получателем для создания/правки/удаления, одновременных сообщений, большого зашифрованного пакета и фонового непрочитанного. Нагрузочный тест сравнивает метаданные+HTTP с передачей пакета через PAWTALK_EVENT_PAYLOADS=1; в режиме пакетов история не запрашивается. Локальный TCP-замер не включает TLS/расшифровку/звук и не является длительной приемкой вместимости.

## Оценка Redis

Redis и общий кеш HTTP-ответов не добавлены. Повторное чтение живого сообщения устранено доставкой зафиксированного снимка; закодированный пакет уже общий внутри одного Go-процесса. Оставшиеся общие кандидаты — зашифрованные строки истории либо неизменяемые вложения, с ключом сервер/канал/ревизия/выборка, ограничением памяти и сбросом при записи. Проверка личности и доступа обязательна до использования кеша; персональные непрочитанные, собственные бюллетени и решения о правах/отзыве не должны переиспользоваться между пользователями. Сначала нужно измерить оставшиеся горячие чтения, затем выбирать кеш в процессе либо отдельный Redis. Cache-aside требует явного сброса и ограничения устаревания; один TTL не обеспечивает немедленный отзыв прав. См. [документацию Redis cache-aside](https://redis.io/docs/latest/develop/use-cases/cache-aside/).

Один локальный A/B-запуск 2026-11-18 (p95 готовности содержимого, миллисекунды):

| Получатели | Событие метаданных плюс HTTP | Зашифрованный пакет через WS | Запросы истории получателями в режиме пакетов |
| --- | ---: | ---: | ---: |
| 100 | 160 | 110 | 0 |
| 500 | 464 | 204 | 0 |
| 1000 | 836 | 327 | 0 |

Оба режима используют текущее общее ядро, тестовых участников и локальный TCP. Одна пачка не включает TLS, расшифровку клиента и голос; это не подтверждение производственной вместимости или длительной пропускной способности.
