# Контракты новых функций чата в исходном коде

[English](chat-features.en.md) · [Архитектура](README.ru.md)

Контракты описывают исходный код, а не ранее опубликованные бинарники.

## Хранение и совместимость

API/data schema остаются равными 2. После проверки идентичности/схемы API 2 оба режима сервера исполняют добавочный идемпотентный DDL membership_features.sql. ID и контексты ключей сохраняются; поддержка медиа расширяет ограничение размера вложений, как описано ниже. Отдельные таблицы хранят активность сеансов, аватар сервера, опросы и бюллетени. Необязательные capabilities ограничивают новые записи; обычный чат со старым API 2 доступен. Manager остается инструментом хоста. API 1 по-прежнему отклоняется без миграции.

## Присутствие, аватары и привязка

Electron powerMonitor сообщает системное время простоя; 300 секунд означают «Отошел». Heartbeat передает статус каждого живого сеанса. Любой активный связанный сеанс делает эффективный профиль доступным; офлайн приоритетнее простоя. Renderer не может вручную задать статус. Аватар сервера использует purpose avatar, resource server-avatar и эффективный профиль автора в контексте аутентифицированного шифрования. Запись защищают роль admin и ожидаемая ревизия; поврежденная картинка не блокирует чат.

Контекст и приватные ключи обмена остаются в main process после закрытия окна кода. Renderer опрашивает проверенные запросы; main process один раз разворачивает окно и передает фокус для входящего запроса. Подтверждение сохраняет прежние формы. Закрытие проверяет свежий статус и отменяет запрос с подписанным доказательством устройства; отменять могут только два участвующих устройства, завершить отмененный запрос нельзя.

## Упоминания и уведомления

Упоминания — зашифрованные диапазоны UTF-16 с ID выбранных профилей. Редактирование сдвигает неизмененные диапазоны и убирает измененные. Сейчас список участников общий для каналов, поскольку доступ серверный. Непрочитанная история сканируется ограниченными страницами, в том числе после переподключения. Пины упоминаний отделены от обычных счетчиков; уведомления обходят мут сервера/чата, но не deafen, настройки звуков и ограничения ОС. Прочитанное и сроки мута локальны для устройства. Абсолютная доставка ОС не гарантируется.

## Сохранение истории чата

История автоматически подгружается у границ списка; настройка 25–500 сообщений задает размер запроса, а не скользящий лимит удаления. Непрерывные блоки открытого чата сохраняют загруженные данные в RAM; переходы по далеким цитатам сохраняют другие блоки и не выдают неизвестные промежутки за загруженную историю. WS обновляет все кешированные блоки; legacy/resync перечитывает кешированные ID выборками не более 500. Выход размонтирует чат и очищает кеш. Каждые 15 секунд авторизованный локальный memory.status проверяет доступную RAM системы (нехватка ниже max(256 МиБ, 5% общего объема)); renderer дополнительно проверяет доступный сигнал JS heap (80% лимита). Только при нехватке памяти удаляются далекие блоки с сохранением max(100, размер порции) сообщений у видимой области и якоря чтения. Проверка не добавляет серверный опрос или новую зависимость. У декодированных изображений остается отдельный ленивый жизненный цикл. Совпадение с закрытым алгоритмом кеша Discord не заявляется; его публичный [API сообщений](https://docs.discord.com/developers/resources/message#get-channel-messages) описывает пагинацию before/after.

## Шифрование опросов и завершение

Вопрос/ответы зашифрованы в сообщении; Server хранит число вариантов, срок, настройки, профили голосовавших, индексы выбора и время как метаданные. Анонимность скрывает личности от участников, но не оператора; скрытые промежуточные результаты не раскрывают счетчики и личности даже автору. Один эффективный профиль имеет один изменяемый/отзываемый бюллетень. При связывании открытые бюллетени объединяются по самому свежему; завершенные результаты не меняются.

Создание атомарно резервирует исходное сообщение и отдельно зашифрованный шаблон итога со стабильным request ID и хешем повтора. Request ID итога защищен от обычной отправки. Итог использует контекст исходного автора/канала и содержит ссылку на опрос, вопрос и варианты, а не заранее угаданные счетчики. Общий таймер Server проверяет сроки каждую секунду и при старте, однократно вставляет сохраненные зашифрованные байты и отдает окончательные счетчики через аутентифицированное чтение. Автор может быть офлайн; остановленный Server обрабатывает пропущенные сроки после запуска. Selfhost остается временным. Автор завершает досрочно; поздние голоса и редактирование опросов запрещены. Для публикации итога не нужен живой сеанс автора. Серверная метка результата показывает отправителя «Система», сохраняя исходный контекст шифрования. Пользователи не могут редактировать или удалять итоги и удалять завершенные опросы; сервер проверяет это независимо от интерфейса. Лимит хранилища и удаление истории могут удалить исходный опрос или итог.

Итог ссылается на исходный опрос; проценты нескольких ответов считаются от числа участников и могут суммарно превышать 100%. При ничьей показаны все лидеры; без голосов победителя нет.

## Доставка событий

server-events-v1 добавляет одну аутентифицированную подписку сервера и короткую сверку номера событий. Она обслуживает чат, уведомления, опросы, изменения состава/профилей и подтверждение привязки на допущенном устройстве. chat-events-v1 остается для прежних сборок; без поддержки или при обрыве используется опрос. Выбранный чат добавляет новые строки, использует кеш цитат/предыдущего сообщения; правки/удаление и resync перечитывают нужные данные. message-events-v1 дополнительно передает зафиксированные зашифрованные пакеты и метаданные удаления через /api/v2/events/messages. Ревизии канала обнаруживают дубли и пропуски; ограниченные очереди переходят к HTTP при resync. Пакеты читаются один раз внутри транзакции записи и сериализуются один раз для подписчиков. Открытое содержимое и корневой ключ не попадают на Server. Доступ, E2EE и контракты request ID/повторов сохраняются. Endpoint, ограничения, сохраненные heartbeat и границы проверки — в [аудите соединений](connection-audit.ru.md).

## Медиа и интерактивные списки

media-files-v1 увеличивает открытый размер зашифрованного вложения до 50 МиБ (шифротекст плюс 16 байт). JSON ограничен 70 МиБ, тайм-аут запросов вложений на Client — 120 секунд. При запуске транзакция расширяет ограничение старой таблицы вложений, копирует зашифрованные байты без изменений и восстанавливает индексы и триггеры владения; API/data остаётся 2. Изображения сохраняют лимит 2 МиБ и проверку сигнатуры. Документы используют application/octet-stream и ссылки скачивания, без HTML-рендеринга и перекодирования. Имена и MIME находятся в зашифрованном содержимом сообщения.

checklists-v1 добавляет таблицу списков с каскадным удалением вместе с сообщением. Название и текст пунктов зашифрованы; Server видит непрозрачные ID пунктов, отметки и политику «все/автор». Только разрешённый автор редактирует содержимое сообщения; участники с chat.write отмечают существующие ID при разрешении политикой. Квитанции мутаций защищают повторы. Редактирование сохраняет отметки оставшихся ID и удаляет исчезнувшие. checklist-events-v1 передаёт отметки внутри подтверждённых событий чата. Отметка увеличивает ревизию канала без перезаписи зашифрованного содержимого. Client отклоняет старые снимки; чтение состояния восстанавливает данные после переподключения/resync. Старые Server и отключённые потоки сохраняют опрос. API Manager не изменён.


`media-gallery-v1` разрешает до двадцати уникальных ID вложений на сообщение: десять файлов и до десяти изображений превью. Новое зашифрованное содержимое содержит `files` либо прежний одиночный `file` с необязательной ссылкой `poster` и длительностью; старые сообщения с одним фото/файлом читаются по-прежнему. Повтор отправки сравнивает весь набор ID независимо от порядка. Привязка атомарна, с прежними проверками владельца/канала/устройства, квотами и каскадным удалением. На устройство допускается до двадцати незавершённых загрузок, срок хранения — тридцать минут для последовательной загрузки нескольких видео. Превью использует существующий ограниченный путь шифрования/загрузки изображений; открытые кадры и имена файлов не попадают в метаданные Server. Числовые API/data и контракт Manager не меняются. Старые Client не отображают новое поле галереи; для нескольких вложений требуется обновление.
