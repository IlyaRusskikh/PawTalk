# Работа над PawTalk

[English](AGENTS.md) · [Индекс знаний агентов](agents/README.ru.md)

Это обязательная точка входа для любого агента. Сначала прочитайте [индекс знаний](agents/README.ru.md), затем правила и навыки, относящиеся к задаче. Перед широким поиском используйте [карту компонентов](agents/architecture/components.md); описания сверяйте с кодом.

- Ограничивайте контекст задачей. Для поиска незнакомых символов и связей сначала используйте Codebase Memory MCP, если он доступен, затем читайте только нужные участки исходников. Для строк, конфигурации и пробелов индекса используйте точечный текстовый поиск. Если поиск уже дал ответ, не повторяйте его по всему репозиторию и не выводите файлы и логи целиком без необходимости.
- Работайте в ветках от актуального `main`, никогда не коммитьте напрямую в `main`. Начинайте новые ветки с имени `rename-me-before-pr`. Перед созданием PR переименуйте ветку по итоговым изменениям. Следуйте [правилам Git](agents/rules/development.md). Push рабочей ветки допустим в рамках порученной работы после проверок. **Merge, создание тегов и публикация требуют отдельных явных разрешений владельца**. По умолчанию squash merge, затем удаление рабочей ветки.
- Сохраняйте AGPL-3.0-only, уведомления о сторонних компонентах, архитектуру и независимые контракты Client/Server/Manager. Не публикуйте секреты, действующие приглашения, персональные данные, `CONTINUE.md`, сгенерированные файлы, загруженные инструменты и результаты сборки. Новые production-зависимости — только после согласования.
- Выбирайте проверки по [маршрутизации тестов](agents/testing/README.md). Перед push выполняйте применимые проверки финального состояния, просматривайте вывод и exit code, запускайте `npm run check:public` и смотрите staged diff. Повторно использовать результаты можно, только если покрываемые ими входные данные и окружение не менялись. Сообщайте о недоступных тестах и различайте unit, synthetic, integration, container, native и испытания с реальными устройствами/сетями. Не скрывайте неудачи.
- Поддерживайте одинаковую фактическую точность русских и английских README, руководств, архитектуры и истории. Технические детали относятся к `architecture/`, пользовательские инструкции — к `docs/`, важные ограничения безопасности — к `SECURITY.md`. Правила геометрии общих форм, кнопок и локализации enum — в [development rules](agents/rules/development.md).
- Релизы следуют [процессу выпуска](architecture/releasing.ru.md): успешный Preflight точного неизменённого SHA `main` и подготовленные артефакты предшествуют отдельным разрешениям создания тега и публикации. Продвигайте **те же проверенные байты**, не пересобирая их. Не заменяйте опубликованные теги, бинарники и образы. Реальные версии и ссылки берите из GitHub Releases, а не исходных манифестов или глобального `releases/latest`. Для прошедшего prepare-only кандидата на неизменённом `main` предпочтителен Promote Existing Preflight с сохранением run/attempt/receipts.
- После создания PR передайте ссылку на его CI владельцу. Не отслеживайте CI без поручения. Отсутствие ответа не является согласием на merge/tag/release.
