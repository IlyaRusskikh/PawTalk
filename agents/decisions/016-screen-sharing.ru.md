# Демонстрация экрана в голосовой комнате

[English](016-screen-sharing.en.md)

Видео демонстрации и необязательный системный звук передаются разными источниками LiveKit в существующей комнате E2EE. В API 2 и API 3 разрешение на публикацию определяется явным правом на источник. В API 3 оба новых источника подчиняются действующему праву говорить при входе и при последующих обновлениях прав. Чат, обработка микрофона и контракты Manager независимы от просмотра.

Electron перечисляет источники для главного окна Client. Выбор источника разрешает один запрос захвата от того же фрейма и требует действия пользователя. Для монитора можно включить захват системного звука Windows. Для окна в поддерживаемых версиях Windows можно включить захват звука дерева процессов приложения через WASAPI. В дорожку может попасть звук других окон того же приложения. Client привязывает доступ к выбранному окну и публикует звук через медиапоток без подключения к локальному выводу. Client зрителя воспроизводит звук только выбранного чужого стрима и учитывает общие настройки отключения звука и вывода.

Список окон Windows также показывает свёрнутые и другие недоступные источники, чтобы объяснить, почему захват нельзя начать. Список обновляется, когда Client снова получает фокус. Для захвата можно выбрать только источники, которые вернул Electron. Варианты разрешения ограничены размером выбранного источника. При сворачивании окна Client приостанавливает публикацию видео LiveKit. Client зрителя показывает заглушку и возвращает видео из той же публикации, когда окно разворачивают. В API 3 по-прежнему запрещена отправка произвольных пакетов данных.

Отдельная медиакомната и новый протокол членства не требуются. Права проверяются серверными тестами, захват — нативным сценарием Windows Electron, голос и чат — интеграцией членства. Старые Client могут обрабатывать системный звук как обычную аудиодорожку, поэтому перед передачей такого звука обновите Client зрителей.
